# 发版流程（给不写代码的人）

> 已经发过 0.1.0 了。以后每改一版，照这份文档做一遍就行。
>
> **最省事的做法：双击项目根目录的 `发版.cmd`，跟着屏幕上的提示走。** 下面是把每一步讲清楚，方便你知道它在干什么、出问题时怎么办。

---

## 一句话版本

```
改完代码 → 双击「启动-测试库.cmd」自己点一遍 → 双击「发版.cmd」→ 按提示走 → 去 GitHub 页面确认
```

---

## 第一步：发版前先自己试一遍

**不要跳过这一步。** 测试能挡住「代码写错了」，但挡不住「功能用起来不对」。

双击 **`启动-测试库.cmd`**（不是 `启动-开发版.cmd`，那个会动你的真实数据）。

它用的是 `.tmp\测试库` 里的假数据，随便点、随便删都不会影响真实的考勤记录。

重点看这几件事：

| 你这次改了什么 | 就重点看什么 |
|---|---|
| 工资表相关 | 随便选个区间，看合计对不对得上你手算的 |
| 发放/预支相关 | 记一笔、冲销一笔，看结余变没变对 |
| 照片相关 | 拖几张照片进去，看缩略图能不能出来、点开是不是原图 |
| 导出相关 | 真的导出一次，用 Excel 打开看数字是不是数值型 |
| 只是改了文字/按钮 | 看那个页面显示对不对 |

**如果有问题：** 别发版，先去改。改完再试。

---

## 第二步：想好版本号

版本号是三段数字：`主.次.修`，例如 `0.1.0`。

| 你这次做的 | 版本号怎么变 | 例子 |
|---|---|---|
| 修了一个 bug、改了文字、调了样式 | 最后一位 +1 | `0.1.0` → `0.1.1` |
| 加了新功能、加了新页面 | 中间一位 +1，最后一位归零 | `0.1.0` → `0.2.0` |
| 大改版、数据格式变了 | 第一位 +1，后两位归零 | `0.1.0` → `1.0.0` |

拿不准就用「修 bug」那档（最后一位 +1），不会有问题。

向导会推荐一个版本号，你直接回车就是用它。

---

## 第三步：双击 `发版.cmd`

会弹出一个黑窗口，向导带你走 8 步：

| 步骤 | 它在干什么 | 大概耗时 |
|---|---|---|
| 1. 检查环境 | 看是不是 git 仓库、有没有装依赖、有没有没提交的改动 | 几秒 |
| 2. 问你版本号 | 屏幕上会显示当前版本和建议的新版本号 | 几秒 |
| 3. 跑测试 | 单元测试 + 两个类型检查 + 构建。**不过就停在这里，什么都不改** | 1-2 分钟 |
| 4. 改版本号 | 改 `package.json` 里的版本号 | 几秒 |
| 5. 写发行说明 | 问你「这一版改了什么」，你打一句话，回车结束 | 半分钟 |
| 6. 打包 | 打出安装版和绿色版两个 exe | 3-5 分钟 |
| 7. 提交 + 推送 | 把代码和版本号提交，打 tag，推到 GitHub | 半分钟 |
| 8. 发 Release | 上传两个 exe 到 GitHub 的 Releases 页面 | 3-8 分钟 |

**全程大概 10-15 分钟**，大部分时间在第 6 步和第 8 步（在打包和上传，你不用管，别关窗口就行）。

### 第 5 步怎么填

就用大白话写，装机的人看得懂最重要。例如：

```
修复工资表导出时金额少一分钱的问题
新增按工地筛选
```

写完一句按回车，可以继续写第二句，不想写了直接回车就结束。

### 中途要不要确认

要。第 2 步之后会问一句「确认继续？」，打 `y` 回车才真的开始。

---

## 第四步：去 GitHub 上确认

发完之后，向导最后会打印一个网址，类似：

```
https://github.com/Guan-bolan/Attendance-Management/releases/tag/v0.2.0
```

打开它，检查三件事：

1. 页面标题是「鑫淼考勤 0.2.0」
2. 下面「Assets」里有两个 exe，大小分别约 120 MB 和 109 MB
3. 点一下其中一个能开始下载

**三个都对 = 发版成功。**

---

## 出问题了怎么办

向导会停下并告诉你原因。按情况处理：

### 第 3 步「测试没过」

```
✗ 单元测试没过
```

**这一版还没发布，版本号也没改，什么都不用担心。** 把屏幕上最后几行红字发给开发，改完代码，重新双击 `发版.cmd`。

### 第 6 步「打包失败」

版本号已经改了，但还没提交、没发版。同样是改完重新双击。

### 第 8 步「发布 Release 失败」

**代码和 tag 已经推上去了，只是安装包没传完。** 不用重新走整个流程，直接在项目目录执行：

```powershell
npm run release
```

这条命令可以重复执行，会覆盖同名文件，不会产生重复的安装包。

### 窗口卡住不动

看最后一行在干什么。如果是在「上传」或「打包」，**别关窗口**，再等几分钟。网慢的时候传 230 MB 要十几分钟。

如果超过 20 分钟还是没动静，可以关掉，然后按上面「第 8 步失败」的办法单独补传。

### 版本号写错了

如果发到一半发现版本号不对：

```powershell
# 撤销这次的提交和 tag（还没推送的话）
git reset --soft HEAD~1
git tag -d v0.2.0
```

然后重新双击 `发版.cmd`。**如果已经推送成功了**，别硬改，直接发一个新版本号盖过去（例如 0.2.1）。

---

## 发完之后还能补改吗

**发行说明可以补。** 直接改 `docs/releases/<版本号>.md`，然后：

```powershell
npm run release
```

会重新上传并更新页面上的说明。

**代码不能补。** 已经发出去的版本就是那一刻的代码。要改就发新版本。

---

## 这个流程在背后做了什么

如果你想知道它到底动了哪些东西：

```
1. 检查      git status / 依赖 / 必要文件
2. 版本号    package.json 的 version 字段
3. 测试      npm run test + 两个 tsc + npm run build
4. 改号      package.json: 0.1.0 → 0.2.0
5. 说明      docs/releases/0.2.0.md（从 _模板.md 生成）
6. 打包      dist\鑫淼考勤-安装版-0.2.0.exe
             dist\鑫淼考勤-绿色版-0.2.0.exe
7. 提交      git commit + git tag v0.2.0 + push
8. 发布      GitHub Release + 上传两个 exe（改名为英文名）
```

对应的命令（给开发看的）：

```powershell
npm run release:check    # 只做体检，什么都不改
npm run release:flow     # 交互式向导（等于双击 发版.cmd）
npm run release          # 只发 Release（代码和 tag 已推好的情况下）
```

## 几个必须知道的事

### 升级不会丢数据

新版会直接读 `%USERPROFILE%\Documents\Attendance\` 里的老数据。数据库结构只加不删，老库会自动升级。

**但装新版之前还是建议先备份一次**：打开旧版 → 设置 → 维护 → 「立即备份」，把 zip 放到别的地方。

### 卸载不会删数据

`electron-builder.yml` 里写死了 `deleteAppDataOnUninstall: false`。卸载程序只删程序本身，`Documents\Attendance` 原样保留。

### 不要手动改 `dist\` 里的东西

`dist\` 是打包产物，每次打包会被覆盖。要改配置改 `electron-builder.yml`。

### 不要删 `docs/releases/_模板.md`

向导每次发版都拿它当底稿。删了就生成不出发行说明。

### 已经发布的 tag 不要删

删了对应的 Release 会失效，那个版本的源码链接也会断。
