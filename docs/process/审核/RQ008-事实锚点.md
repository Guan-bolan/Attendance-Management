# RQ-008 事实锚点（只读摸底结论摘要）

来源：只读调研子智能体（2026-11-12），逐条带 `文件:行号`；全文见当次会话记录。
用途：写 `docs/plans/PL-005-*` 的人直接读这份，不必重复摸底。**这不是方案，只是现状。**

## 1. 两条既有「整库级」链路

**① 数据目录迁移 `migrateDataRoot`**（`src/main/services/migrateDirs.ts:1125-1432`）
入口 `migrate:dataRoot`（`ipc.ts:1455`）→ `assertWritableNow()`（`:1130`）→ 拒 `ATT_DATA_ROOT` 接管（`:1132-1140`）→ `validateDirTarget(role:'data')`（`:1144`）→ 目标必须不存在或空（`:1156-1175`）→ 暂存目录建在目标**同级**（`stagingDirFor` `:90-93`）→ 停收件箱 watcher（`:1214`）→ 抢写锁（`:1219`）→ `checkpoint` + `VACUUM INTO`（`:1223-1230`）→ pre-migrate 快照写进暂存目录（`:1236-1241`）→ 复制 snapshots/thumbs/archives/photos/inbox（`:1186-1192`）→ 校验（`verifyStaged` `:878-921`）→ 三个路径设置与快照/档案绝对路径写进**新库副本**（`rewriteStagedDb` `:1031-1097`）→ 指针预写 tmp+fsync（`paths.ts:266-302`）→ 一次 `renameSync` 落位（`:1335`）→ 指针原子改名（`:1340`）→ `markPendingRestart(abs)`（`:1347`）。
**不重开连接**（当前进程继续连旧库）；成功路径**不恢复** inbox watcher。失败/取消：落位前删暂存目录+临时指针+恢复 watcher（`:1374-1378`）；落位后失败反向 rename 回滚（`:341-350`）。

**② 快照恢复 `restoreSnapshot`**（`src/main/services/snapshot.ts:759-841`）
`snapshots:restore`（`ipc.ts:1048`）→ `resolveTarget`（id 或绝对路径双形态 `:612-653`）→ `assertSqliteFile` 查魔数（`:656-685`）→ 拒「用库文件恢复自己」（`:764`）→ 自留 `pre-restore`（`:768`）→ `detach(db)`（`:688-701`）→ `replaceDbFile` 删 `-wal`/`-shm` 后换文件（`:704-712`）→ `reopen` = `openDb` + `setDb` + `migrate`（`:715-721`）→ 补登记两份快照（`:730-740`）。
**不需要重启**（`:750`）。失败兜底：换文件失败重开原库（`:772-791`）；重开后迁移失败用 pre-restore 写回再开（`:794-821`）。
→ **推论：RQ-008 的「恢复整库」形态更接近 ①（换目录 + 重启），不是 ②。**

## 2. 新功能必须遵守的既有约定（14 条，逐条已核）

1. 两把锁顺序固定：`pendingRestartRoot` 先判、`migrating` 后判（`migrateDirs.ts:211-222`；`ipc.ts:240-253`）。写操作统一走这张表，别自己判。
2. 只读白名单 + 默认拒绝（`ipc.ts:143-156`）。判据是「不碰库、不碰数据目录」：`payments:export`（查库+写用户选的文件）算只读（`:212-217`）。**恢复整库绝不能进白名单**。
3. `VACUUM INTO` 必须配 `checkpoint`，禁止裸拷 `.db`（`snapshot.ts:4-6`；调用点 `snapshot.ts:331+345`、`migrateDirs.ts:1223+1225`、`:774`）。不能在事务里；路径单引号要双写。
4. zip 条目：包根直放、**不套同名顶层目录**（`xlsx.ts:1163-1167`、`map.md:91`）；条目名正斜杠、削开头 `/`（`xlsx.ts:1203-1206`）；去重键 = 条目名小写（`:1218-1220`）；archiver 自己不去重（`:1211-1217`：实测 1157 条 / 125 张）。
5. `resolveInside` 是唯一越界拦截（`paths.ts:505-519`）；调用点 `migrateDirs.ts:548`、`:697`、`xlsx.ts:1077`、`ipc.ts:725`。**新功能读/解压用户给的文件必须过它**（zip slip）。
6. 数据根指针：先探针写 tmp+fsync → 落位 → 原子改名；落位后写指针失败要整段回滚（`paths.ts:277-284`、`migrateDirs.ts:1411-1423`）。指针目标必须同时有目录与 `app.db`（`paths.ts:361-374`）。
7. `snapshots.path` / `archives.path` 存绝对路径，迁移时只改副本（`migrateDirs.ts:1019-1023`、`:1054-1082`）→ 换机后这些路径全失效、列表标 `missing`（`snapshot.ts:471-474`，既有行为）。
8. 迁移只写副本、不写旧库（P5）（`migrateDirs.ts:1017-1023`、`test:590-593`）。新功能同理：动主库前先留退路。
9. 临时目录必须在目标**同级**，才能一次原子 rename（`migrateDirs.ts:82-93`）。
10. 空串 = 未设置；原值等于「旧根下默认值」时改写为空串，让重启后回落新根默认值（`migrateDirs.ts:951-982`）→ **B6「改写成本机默认位置」应复用这套口径**。
11. **恢复 ≠ 迁移**：快照恢复不重启（`snapshot.ts:750`）、目录迁移必须重启（`migrateDirs.ts:1347`）。RQ-008 按 YG 口径 B7 走「必须重启」。
12. dialog 只在 ipc 层：`export/xlsx.ts` 不碰 dialog（`ipc.ts:414-419`）；保存框 `showSaveDialog`（`ipc.ts:831-847`、`:1238-1256`），选目录 `showOpenDialog` + `openDirectory`（`:1425-1435`）。
13. 通道命名 `域:动作`；处理器表 `Record<Channel, Handler>`（`ipc.ts:472`）；错误一律 `DbError` + `E_xxx`。
14. 快照列表以磁盘为准（`snapshot.ts:7-9`）：文件在但没登记给 `id:0`。

## 3. 新增通道的连带面（必须同批改）

`constants.ts` 的 `CHANNELS`（`:7-142`）→ `ipc.ts` 的 `buildHandlers`（`:472`）→ `READ_ONLY_CHANNELS`（`:157-223`）→ `renderer/src/api.ts` 手抄类型与方法。
`src/preload/index.ts` **不用改**（白名单由 CHANNELS 生成）；`registerIpc` 不用改（遍历注册）。

- 漏改的后果：`Record<Channel, Handler>` 让「CHANNELS 加了表里没写」和「表里写了 CHANNELS 没加」都直接 tsc 报错；运行期还有 `E_IPC_NOT_REGISTERED` 兜底（`ipc.ts:1516-1519`）。
- **`withMigrateGuard` 只遍历 `CHANNELS`**（`ipc.ts:235`）。
- `migrateDirs.test.ts:609-657`（P1）断言 `blocked.length === CHANNELS.length - READ_ONLY_CHANNELS.size`，且每条必须 `E_DB_LOCKED` + message 含「请重启」→ 新通道进不进白名单都会改这条的计数，只要两处同步就不红。
- `migrateDirs.test.ts:659-736`（P2）在迁移中途用空载荷逐个调 handler：非白名单必须 `E_DB_LOCKED`，白名单必须**不是** `E_DB_LOCKED`。异步 reject 被吞成 `code:null`（`:678-680`）→ 这条对只读通道偏宽松。
- `constants.test.ts:11` 断言 CHANNELS 无重复；`ipc.test.ts:145` 要求新通道有处理器；`snapshot.test.ts:255-322` 钉住快照恢复语义。

## 4. 三处会挡路的既有缺口（现状，非建议）

1. **`app:showItemInFolder` 只接受 `.xlsx`**（`ipc.ts:585-592`）→ 备份 zip 想「导出后定位文件」会被拒。
2. **仓里没有「选文件」的对话框用法**：`settings:pickDir` 只有 `openDirectory`（`ipc.ts:1430`）→ 恢复要选 zip 得新写一条 handler。
3. **没有直接声明的解压库**：`package.json` 运行期依赖里只有 `archiver`（压缩侧）；`unzipper@0.10.14` / `jszip@3.10.2` 都只是 `exceljs` 的传递依赖。

## 5. 调研方明确标记的「不确定项」

- 「换机后恢复」仓库里**没有既有实现可参照**（现有恢复只换 `app.db` 一个文件，不含照片、不含指针）。
- 备份该含哪几类目录，代码里没有判据（迁移搬的是五类：snapshots/thumbs/archives/photos/inbox）。← YG 已定 B2：库 + photos + archives。
- `unzipper`/`jszip` 会不会被打进产物，未跑 build 无法确定（本次边界不许跑）。
- 未读：`docs/DELIVERY.md`、`docs/decisions.md`、`electron-builder.yml`、`services/archive.ts`、`services/inbox.ts`。
- `migrateDirs.ts:984-1012` 有一段近乎重复的 `RewriteStagedInput` 注释块，疑似编辑残留（不影响行为，未确认是否有意）。
