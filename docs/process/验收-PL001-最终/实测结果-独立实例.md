# 三、数据安全专项结论

**1）有没有任何拒绝路径改了库？** 没有。逐条验过的拒绝场景（每条都取了前后对照）：

# 四、回归风险（没覆盖到、但真实使用会撞到）

1. **每日录入的交互链**（保存后清空哪些字段、重复记录「覆盖/并入/取消」、已标上班再标另一张的提示、备注列宽/长工地名溢出、当天记录表横滚、`Ctrl+A/C/V/X/Z`）——本次只验了字段布局、工数折算、判重拒绝与照片框内容，**保存与冲突弹窗没跑**，这是最容易出错的一块。
2. **批量登记的界面半场**（拼音首字母搜索、生成后勾选清空、失败后勾选保留、结果表逐条编辑）——只验了 IPC 层的「N 人 N 条 + 照片位 IN/OUT」与同键拒绝。
3. **设置页的目录链路**（收件箱即时生效、数据目录迁移必须重启、迁移期 `E_DB_LOCKED`、环境变量接管时按钮禁用）——一条都没实跑，只有单测 27 项通过作参考。
4. **导出弹窗与文件名**：保存对话框在无头环境驱动不了，`<主题>_<起>_<止>.xlsx` 与「导出后自动定位文件」都没有实测。
5. **缺记录提醒**：库太新时直接返回空（`reason: db-too-new`），首次安装的用户看不到「共 N 天无记录」，容易被当成功能坏了。
6. **打包交付**：现在 `dist` 里的两个 exe 早于源码一天，直接发给 YG 会缺本批功能——必须重新打包。
7. 真实库在验收期间被外部启停两次，说明有人同时在用这台机；正式交付前建议重跑一次门禁（test / 两个 tsc / build）。

# 五、一句话结论

**不能按现在这份 `dist` 交付**：源码侧 0~6、9~14、16 主体（约 100 条）实测通过，但 **17.1 / 17.2（打包产物过期、asar 里没有本批功能）** 与 **16.2（迁移失败目标目录残留）、16.4（汇总页文案含「分钟」）** 四条不通过；区 7（每日录入）、区 8（批量登记）、区 15（设置目录链路）有大片交互未验，交付前必须补一轮 UI 验收 + 重新打包。
