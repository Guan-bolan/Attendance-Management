1. **未发现会让钱变化的缺陷**：v8→v12 迁移、快照恢复、整库备份/恢复三条路上，每个工人的结余与每个区间的工资表都逐人逐分逐字段相同；
   唯一被迁移改动的钱是 012 有意插的那条负数冲销（何秀兰 −100000 分），它是**修双算的设计**，不是缺陷。

## 7. 不符项（期望 / 实际 / 位置 / 修法 / 反证断言）

**7-1〔唯一一处，测试强度，非产品缺陷〕只读通道的断言盲区**

- **期望**：「遍历全部通道」这条用例能证明「新加的 `assertDate` 不会把只读通道打挂」，且能发现只读通道被新的参数校验改坏。
- **实际**：断言只有 `not.toBe('E_DB_LOCKED')`，任何其它错误码（`E_MIGRATE_FAILED`、`E_VALIDATION`、甚至裸 `TypeError`）都能通过；

- **位置**：`src/main/services/migrateDirs.test.ts:736-749`（断言）；`src/main/ipc.ts:1358`（`payroll:export` 的早退）与 `:1526`（`advances:export` 的 `assertDate`）。
- **修法**（任一，都不改产品行为）：
  1. 用例里对只读通道补一条**正向**断言：`payroll:export` / `advances:export` 用 `{}` 调 → `expect(code).toBe('E_VALIDATION')`；
  2. 再加一条**回证**：用 `{from:'2026-11-01', to:'bad'}` 调 `payroll:export`，断言 `E_VALIDATION` 且 `detail.got === 'bad'`（证明新 `assertDate` 真的在跑）；

- **反证断言**（改完之后应变成：现在能发现旧行为的反向）：
  ```ts
  // 现在（弱）：任何错误码都过
  expect(item.code).not.toBe('E_DB_LOCKED')
  // 修后（强）：只接受「跑通」或「参数校验拦下」

  // 且真的打到了新校验
  const hit = await handlers['payroll:export']({ from: '2026-11-01', to: 'bad' }).catch(e => e)
  expect(hit.code).toBe('E_VALIDATION'); expect(hit.detail.got).toBe('bad')
  ```

**除此之外，未发现「钱变了 / 建了空库 / 改了本机指针 / 用错上限 / 行数错了」的不符项。禁止凑数，就这一条。**
