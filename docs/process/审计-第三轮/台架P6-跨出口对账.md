## 结论（三句话）

- 族内：**5 个出口 × 4 人，36 个金额格 + 12 个工数格 + 4 个加班分钟格，差异 0 处**（出口④「汇总页按人表格」设计上没有金额列，只对工数/加班）。
- 族间：差异与设计**逐条对上**——族(a)−族(b) 逐人恰好等于「> 今天」那条的应发（张伟 39000 / 王芳 27500 / 李强 0 / 赵六 0，合计 66500）；族(c)−族(a) 只有赵六 1 分（31563 vs 31562），其余 0，落在 C15b 明文允许的 1 分内。
- **未发现「同一笔钱两处不同」**。§6 没有不符项；只有两条口径陷阱/已知差异，均已附反证断言。

## 3. 族(c) vs 族(a)：1 分差证据（单位：分）

取整边界样本（赵六，日薪 30000 / 餐补 1500）：
- 区间内 `FULL + 加班 1 分` → 精确 30000 + 62.5 + 1500 = **31562.5**
- 区间外（早于 from）`AM + 加班 1 分` → 精确 15000 + 62.5 + 750 = **15812.5**

| 工人 | 族(a) | 族(c) `periodNetForRange` | 差 | 说明 |
|---|---|---|---|---|
| 张伟 | 70500 | 70500 | 0 | |
| 王芳 | 41250 | 41250 | 0 | |
| 李强 | 19445 | 19445 | 0 | 精确值本就落不整，但两族都只取整一次 |
| 赵六 | **31563** | **31562** | **1** | 族(a)=ceil(31562.5)=31563；族(c)=ceil(47375.0) − ceil(15812.5)=47375−15813=31562 |

- 断言：`|族(a) − 族(c)| ≤ 1 分` 全 4 人通过；差恰 1 分只出现在赵六。
- 这是 **C15b 明文允许的**：ceil(A∪B) − ceil(B) ≠ ceil(A)，差值上界 1 分。不是缺陷，未修。
- **口径陷阱（已记账，不是缺陷）**：`periodNetForRange(db, from, to, asOf?)` 的 `asOf` 缺省是**本地今天**，不是「max(今天, 区间末端)」；后者是**调用方**的责任（`archive.ts:2686`：`to > todayIso() ? to : undefined`）。若漏传，同一份数据会算出：张伟 31500（少 39000）、赵六 31563（与族(a) 同值、掩盖了那 1 分）。生产里目前只有 `archive.ts` 一个调用点，写法正确。

## 4. 结余侧三处同值 + 发放导出结余区（单位：分）

| 工人 | 发放页 periodDueCents | 发放页 totalDueCents | 预支页 creditBoard.dueCents | workerBalance.totalDueCents | 发放页 balanceCents | 预支页 availableCents | workerBalance.balanceCents |
|---|---|---|---|---|---|---|---|
| 张伟 | 31500 | 31500 | 31500 | 31500 | 1500 | 1500 | 1500 |
| 王芳 | 13750 | 13750 | 13750 | 13750 | 13750 | 13750 | 13750 |
| 李强 | 19445 | 19445 | 19445 | 19445 | 14445 | 14445 | 14445 |
| 赵六 | 31563 | 47375 | 47375 | 47375 | 47375 | 47375 | 47375 |

- 页脚合计也同值：`creditBoard.totalDueCents === balanceBoard.totals.totalDueCents`，`totalAvailableCents === totals.balanceCents`。
- 发放导出的「截至今天各人总结余」（`exportPaymentsXlsx` 的结余区，标题行 `截至今天各人总结余` → 子表头 → 逐人）：逐人四列与 `balanceBoard` **完全相同**；**换区间不变**——用 `[2026-11-03, 2026-11-23]` 与 `[2026-11-11, 2026-11-12]` 各导一次，逐人 `[累计应发, 累计预支, 累计已发, 结余]` 两两相等，且都等于 balanceBoard。
- 赵六那行同时暴露一个**设计内的口径差**：区间应发 31563，累计应发 47375 —— 但 **47375 ≠ 31563 + 15813 = 47376**。原因是累计应发是「全史一次精确累加只取整一次」= ceil(31562.5 + 15812.5)，而「区间 + 区间外各自取整再相加」会多 1 分。这与 C15b 是同一现象，**不是两处同值不一致**（两者口径不同，且代码里只有一处实现）。
- 页面层是纯显示：`Payments.tsx` / `Advances.tsx` 直接渲染 `periodDueCents` / `totalDueCents` / `balanceCents` / `availableCents`，没有第二次加减（`Payments.tsx:1317-1318` 注释明说不做加减）。

## 5. 预支合计 vs 明细（单位：分）

含冲销（区间 2026-10-04~2026-11-23，4 笔）：明细 `[5000, 20000, 10000, -10000]` → 分域相加 **25000**；末行「合计（4 笔）」金额格 **25000**；`exportAdvancesXlsx` 的 `result.totalCents` **25000**；`listAdvances` 的 SUM **25000**。差 **0 分**。
不含冲销（默认）：被冲销的原记录与冲销行成对消失 → 明细 `[5000, 20000]` 合计 **25000** = 合计行。两种勾选净额相同（被冲销的那对本来就是 0），但笔数从 4 变 2 —— 符合设计。

## 6. 不符项

**无。未发现不一致。**（本节没有凑数项。）

两条「不是缺陷但要记账」的观察，附反证断言：
1. **族(c) 的 cut 口径靠调用方传参**，`periodNetForRange` 缺省 = 今天。
   期望：cut = max(今天, 区间末端)；实际（不传 asOf 时）：cut = 今天。位置 `src/main/repo/balance.ts:378-387`。
   修法：**不改**（签名与默认值是结余侧口径，改默认会连带影响别处）；已由唯一调用点 `src/main/services/archive.ts:2686` 显式传对。
   反证断言：`M3` 用例里按 archive.ts 同形规则传 `asOf = to > 今天 ? to : undefined` → 赵六 31562（差 1 分）；若改传 `asOf = 今天`，同一份数据会变成 31563 且张伟少 39000 —— 说明这个参数不能靠默认值兜。
2. **区间应发 + 区间外 ≠ 累计应发（差 1 分）**，赵六 31563 + 15813 = 47376 vs 累计 47375。
   期望：差 ≤ 1 分（口径 19 / C15b 同一现象）；实际：差 1 分。位置 `payroll.ts#sumAmounts` 的取整次数差异。
   修法：**不改**（已知且明确不修）。
   反证断言：`M4` 里 `totalDue` 断言为 47375，而不是 31563+15813。

## 7. 没覆盖的部分

- 出口②的 `workerIds` 筛人分支（`exportPayrollRangeXlsx` 第 5 参数）：只跑了全员导出。
- 出口⑤只验了**新生成**的档案包；老包（迁移前 schema、缺 `payments`/`carryovers` 表）下的 `readArchiveForViewer` 未覆盖。
- 档案查看器的「区间小计 `paymentsSubtotal.dueCents`」（Σ 每人 total，逐人取整后相加）与族(c) 的口径差未逐一比对——它只对档案库、不进结余。
- 预支导出的「按人」分支、发放导出的「按人」分支（`exportPaymentsOfWorkerXlsx`）只验了全员。
- 清库闸门的 UI 勾选/结转流程（`purgeArchiveRange` 真跑清库、结转生成后结余变化）未跑；只验了 `periodNetForRange` 口径本身。
- 「不同区间取整次数不同」（月表逐月相加 vs 全年一次）这类口径 19 的已知差异未穷举；`formatUnits` 与 Excel 半分位显示差异按要求不修、未验。
- 并发/多进程（两个窗口同时导出）、真实数据目录下的性能与锁行为未覆盖。
