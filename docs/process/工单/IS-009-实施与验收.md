## 5. 偏离工单的地方（3 处，都有实测依据）

1. **「时段」列加了 render 夹取 + Tooltip（工单只让改列宽）**
   76px 的内容盒只有 60px，而按小时记录的标签「按小时 3 小时」自然宽 **89.05**、`按小时 23.5 小时` 更宽 → 实测顶出单元格 **29.05px**，直接压在「出勤」的「3 小时」上（`shots/crop-period-column.png` 是未夹取时的串字证据）。
   给「时段」加宽到 106 才够 3 小时那种标签，`23.5 小时` 要 126 → 在 848 预算里无解，所以改成夹取 + Tooltip（`shots/final-10-hours-period-tooltip.png`：标签显示「按小…」，悬停出「按小时 3 小时」）。
2. **备注列加了 `onCell: () => ({ title: '' })`**
   工单只说保留 `ellipsis: true` + Tooltip；但 antd 在 `ellipsis` 时会自己写一个原生 `title`，不清掉悬停会同时弹原生和 antd 两个提示。
3. **工数 116 的真实读写**（工单注释的「自然宽 104」是「折行后最长一行」，不是真实自然宽）
   内容盒 100。「整天」折算行 natural 100 → 刚好塞下（余量 0）；「按小时」折算行 `3 小时 ÷ 9 小时 = 0.33 工` 真实自然宽 **134.38** → 折两行、行高 83px。**改前 120px（内容盒 104）也是两行**，用 DOM 试验证过（`units-width-experiment.log`：col=120 / 116 / 150 三档都是 2 行、行高 83）——不是本次引入。

## 10. 残留风险

1. **窗口再窄 < 1066 会重新出横滚条**（改前阈值 ~1245）；1066~1098 不溢出但备注 0 宽。
2. **列内容过长的出口没做夹取**：工人 80（4 字姓名 + `#seq`）、工地 88（5 字以上）、加班 76（`23.5 小时`）、出勤 76（`23.5 小时` ≈ 55 内容盒 60 勉强）、日期 88（余量 0.42px）——这些列一旦内容超宽会像改前的「时段」一样顶出，只有「时段」和「备注」加了夹取。
3. **批量登记没动**：声明宽合计 900 > 容器 896，靠 `table-layout: auto` 压进 896；谁给它加 `tableLayout="fixed"` 就会立刻溢出（IS-009 §回归风险里的警告仍然有效）。
4. 本次改后测量用的是包含并行任务 `App.tsx`/`main/index.ts`（页头/菜单）改动的新构建，所以 `innerH` 从 765 变 739；**横向几何没变**（innerW 1167 时 content clientW 两次都是 962）。
