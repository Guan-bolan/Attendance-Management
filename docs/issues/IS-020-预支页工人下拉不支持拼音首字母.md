# IS-020 预支页两个「选工人」下拉不能用拼音首字母搜索

状态：**已修**（2026-11-13；按 `docs/TASKBOOKS.md` §13 先定位、后落单、再修）
发现日期：2026-11-13
发现人：YG（实操反馈）
定位：只读定位 agent（triage，未改任何文件）

## 现象

「预支」页里给工人下拉框输入**拼音首字母**（如 `sxw`）搜不到人——下拉直接变空；输入**汉字**（如 `水`）正常。

其他页面的同类下拉都能用首字母搜（每日录入 / 批量登记 / 工资发放 / 汇总 / 记录编辑弹窗）。

## 坐标

- 预支页 · 「记一笔预支」卡片第一行的工人下拉：`src/renderer/src/pages/Advances.tsx:719`（`Advances` 组件）
- 预支页 · 「预支记录」卡片右上「全部工人」筛选下拉：`src/renderer/src/pages/Advances.tsx:1027`（同一组件）
- **同页同源的对照组（本来就是对的）**：导出弹窗「按人」多选 `Advances.tsx:1182` —— 它有 `filterOption={filterOptionByName}`（`:1186`）

## 根因

这两个 `<Select>` 都写了 `showSearch` + `optionFilterProp="label"`，**但没写 `filterOption`**，于是走 rc-select 的默认过滤。

`node_modules/rc-select/lib/hooks/useFilterOptions.js`（**已逐行核实**）：

```js
var customizeFilter = typeof filterOption === 'function';        // :28
var filterFunc = customizeFilter ? filterOption : function (_, option) {
  if (optionFilterProp) return includes(option[optionFilterProp], upperSearch);  // :32-34 只做字面子串
  ...
}
```

- `:17` 的 `includes` 就是 `join('').toUpperCase().includes(search)` —— **纯字面子串**，不认拼音。
- 而 `label` 里只有人名（`Advances.tsx:687-690`：`w.seq > 1 ? \`${w.name} #${w.seq}\` : w.name`），**没有任何拼音字段**。
- 所以 `sxw` 在「水小文」里找不到 → 整批被过滤掉 → 下拉空。
- `filterOption` 一旦是**函数**，rc-select 走 `customizeFilter` 分支，**`optionFilterProp` 被完全忽略** —— 这就是「同页导出弹窗能搜、这两个不能搜」的唯一差异点。

**为什么偏偏这两处**：`showSearch + optionFilterProp="label"` 是**工地下拉**的写法（工地名没有拼音需求，所以那种写法是对的）。这两个工人下拉是照工地那个模式抄的，漏了工人侧必须的 `filterOption={filterOptionByName}`。

**佐证**：`Advances.tsx:77` 已经 `import { filterOptionByName }`，但全文件只在 `:1186` 用过一次。

## 修复建议（2026-11-13 已按此实施）

给 `Advances.tsx:719` 与 `:1027` 两个 `<Select>` 加 `filterOption={filterOptionByName}`；并把它们的 `optionFilterProp="label"` 去掉（函数式 `filterOption` 下它被忽略，留着会误导后来人以为这里是标签匹配；工地下拉那几处保持不动）。

**副作用**（逐条核过）：
- **不影响 `label` 显示**：`filterOption` 只决定「这一项过不过滤」，不参与渲染。
- **「按姓名搜」不会失效，反而更宽**：`pinyin.ts#matchName` 同时判 `name.includes(kw)` 与 `lowerName.includes(lowerKw)`，是原来字面匹配的**超集**；差别只有两点：会先 `trim()`（前后空格不再算不匹配）、拼音串参与匹配。
- **不改变排序**：`filterOption` 只返回布尔，rc-select 按 `options` 原顺序输出。
- **`allowClear` 行为不变**（`:1031` 的清空 → `onChange(value ?? null)` 不受影响）。
- **导出弹窗不受影响**：两处共用 `workerOptions`（`:687`），但本方案不动 `options` 结构。
