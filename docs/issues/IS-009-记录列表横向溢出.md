## 现象

每日录入 / 批量登记录完记录后，下方条目**超出整体的框**，必须拖底部横向滚动条才能看全。

> **报告人复核（2026-11-09）**：YG 确认「批量登记也溢出」是看到每日录入后的先入推断，**并未亲眼见过**。因此本工单范围收窄为**仅每日录入**；批量登记不改（triage 亦警告：给它加 `tableLayout="fixed"` 反而会把 bug 复制到那页）。


## 复现结论

| 页面 | 能否复现 | 数据 |
|---|---|---|
| **每日录入** | **能**（3/3 轮） | 容器可用 **896px**，`<table>` 实宽 **1032px** → 溢出 **136px**，页面出现横向滚动条 |
| **批量登记** | **不能**（0/3，窗口 1180~650 宽都不溢） | 表声明宽 900px，浏览器自动布局压到 896 → 溢出 0 |

批量登记那页需要 YG 补一张截图或说明当时窗口宽度，否则只能按「不复现」处理。

## 根因（一句话）

「当天记录」表的列宽是写死的，合计 **1032px**（数据列 984 + antd 展开列 48）超过容器可用的 **896px**；又因为备注列设了 `ellipsis: true`，rc-table 把整表钉成 `table-layout: fixed`——固定布局**不压缩列宽**，于是表格实宽恒为 1032px 不随窗口变；从 `<table>` 到 `Layout.Content` 之间六层全是 `overflow-x: visible`，这 136px 穿透卡片边框，被唯一 `overflow:auto` 的内容区接住，表现成「条目穿出框 + 底部横滚条」。

## 附带缺陷（同一处的第二张脸）

**备注列被挤成 0 宽**：所有其它列都写了固定宽，只有备注自适应，固定布局下它拿到 **0.00px** —— 内容被裁光、列头只剩一丝。就算把横滚修掉，备注看不见也是 bug。

## 修法（采用 A）

只改 `Daily.tsx` 的列宽数字，让固定列合计 + 展开列 ≤ **856**（给 896 留缓冲）：

```
日期 88 · 工人 80 · 工地 88 · 时段 76 · 出勤 76 · 工数 116 · 加班 76 · 照片 112 · 删除 68
= 780 + 展开列 48 = 828 < 896，备注自适应拿到 ~68px
```

硬约束：工数 ≥116、照片 ≥110（两张 44 缩略图 + 间距 + 内边距）。

**不采用的做法**：

- 外层 `overflow-x: hidden` —— 只是藏滚动条，右侧照片/删除列被永久裁掉，比现在更糟
- `scroll={{ x: 1032 }}` —— 滚动条从页面挪进卡片内，总宽仍超标，属止血
- 去掉 `ellipsis` 退回 auto 布局 —— 能消横滚但长备注换行、行高变高，观感变化大
- **给批量登记加 `tableLayout="fixed"`** —— 它声明宽 900 > 896，一加就把 bug 复制到第二页

### 过程中的两处口径修正（保留下次参考）

1. triage 说「照片列 132 下限 110」，实测**下限 110 正确**；但「工数自然宽 104」是**折行后最长一行**，`按小时` 折算行真实自然宽 **134.38** → 本来就会折两行，**不是本次引入**（120/116/150 三档 DOM 试验均两行）。
2. 计划里写「6 字工地名顶出 12px」，实测**不成立**：antd 单元格有 `overflow-wrap: break-word`，长名会**折成两行**（不压邻列但多占 22px 行高）。仍按「夹取 + 悬停」修掉，把任意超长封死。

### 残留阈值

- `innerW < 1066` 会重新横向溢出；**1066~1098 不溢出但备注又变 0 宽**
- 未做夹取的列超宽仍会折行：日期（余量 0.42px）、出勤/加班（`23.5 小时`）
- **批量登记声明宽 900 > 容器 896**，靠 `table-layout: auto` 压着——**谁给它加 `tableLayout="fixed"` 就立刻溢出**
