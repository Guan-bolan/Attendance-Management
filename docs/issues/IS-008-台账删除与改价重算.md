# IS-008 台账：可删除（仅限无记录）、按钮改名、改价追溯重算

状态：**已完成**（2026-11-09）
提出人：YG
涉及：`repo/workers.ts`、`repo/sites.ts`、`services/recalc.ts`、`Workers.tsx`、`Sites.tsx`、`ipc.ts`、`constants.ts`、`api.ts`

---

## 1. 工人 / 工地可删除（硬删，仅限无记录者）

- **能真删的只有「零考勤、零预支、零结算关联」的工人**；有任何历史 → 删除按钮禁用，提示「该工人有 N 条考勤记录，只能停用」
- 工地同理：有任何考勤/归档引用的工地不可删
- 停用与删除是两个动作：
  - 停用 = 保留在列表（有「显示停用」开关）
  - 删除 = 从列表彻底消失，不可恢复
- 删除前二次确认，写明「删除后不可恢复」

## 2. 「价 / 覆盖」按钮改名「编辑」

- 工人台账行尾按钮文字改为 **编辑**
- 点开仍是现有抽屉（价历史 + 口径覆盖），**保持一屏，不拆页签**

## 3. 改日薪要追溯重算（推翻旧的「固化不追溯」）

**规则**（YG 原话）：
```
2026-10-01 日薪 500、2026-11-01 日薪 600
→ 10 月每条考勤按 500，11 月起按 600
现在把 10-01 那条改成 800
→ 10-01 ~ 10-31 全部按 800 重算（金额立刻变）
→ 11-01 起仍是 600
```

**实现要求**：

- 修改价（改金额）、新增价、删除价 → **都触发受影响区间的重算**
- 受影响区间 = `[该价生效日, 下一条价生效日 − 1]`；删除价时用**前一条价**回填该区间
- 重算内容：`entries.daily_wage_cents`、`entries.meal_allowance_cents`（金额不落库，改完自动生效）
- **标准工日 / 加班折算不在本次范围**，仍按录入时固化（YG 已确认）
- **锁定保护**：受影响区间内若有 `paid` 的结算单 → **拒绝改价**，提示「2026-10 已结算锁定，需先解锁再改价」
- **重算前自动快照**（`manual`）
- 返回值带 `{ affectedEntries, from, to }`，界面提示「已按新价重算 23 条记录」

## 验收

- [ ] 无记录工人能删；有 1 条考勤的删不掉且提示条数
- [ ] 无记录工地能删；有考勤的删不掉
- [ ] 删除后列表消失，`workers` 表行数减少，历史记录不受影响
- [ ] 按钮文字是「编辑」，点开还是原来的抽屉（一屏）
- [ ] 张伟 10 月按 500 录了 3 条 → 把 10-01 的价改成 800 → 这 3 条记录的日薪变 800，工资表金额按 800 重算
- [ ] 同时把 11-01 的价设成 600 → 11 月记录仍按 600，不受 10 月改价影响
- [ ] 改价前自动生成快照
- [ ] 10 月已「标记已发放」→ 改 10-01 的价被拒绝，提示先解锁
- [ ] 新增一条 10-15 的价 700 → 10-15~10-31 按 700，10-01~10-14 仍 500
- [ ] 删除 10-01 的价 → 10 月回落到更早的价（没有更早的则报错提示）

## 约束

- 只动 `daily_wage_cents` / `meal_allowance_cents` 两个固化列，**不动** `std_minutes` / `overtime_unit_minutes`
- 全部在单事务内，失败回滚
- 不改数据库结构（`worker_rates` 已有 `effective_from`）
