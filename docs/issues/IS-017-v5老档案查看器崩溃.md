# IS-017 v5 老档案用查看器会崩（`no such column: slot`）

状态：**已修**（2026-11-11）
发现日期：2026-11-11
发现人：PL-004 T11 实施 agent（写老档案用例时撞到）
来源：`docs/plans/PL-004-sds.md` T11 遗留第 3 条

## 现象

打开**v5 时期的老档案**（`schemaVersion <= 5`，即 `006_entry_photo_slot.sql` 之前打的包）→ 查看器直接崩：

```
SQLITE_ERROR: no such column: slot
```

用户视角：档案柜里点「打开」，页面报错、看不到该档案的任何内容。档案本身没坏——校验的 22 项照样能过，只是查看路径崩了。

## 坐标

- 崩溃链路：`services/archive.ts#readArchiveForViewer` → `repo/entries.ts#listEntries` → `photosOfMany`
- 硬选 `slot` 的那条 SQL 在 `repo/entries.ts` 的照片读取路径（`photosOf` / `photosOfMany`）
- 老档案没有该列：`006_entry_photo_slot.sql` 之前打的包，`entry_photos` 只有 `(entry_id, photo_id)`

## 根因假设

`slot` 是 006 迁移加的列。**主库**升级时会被迁移补齐，所以读主库永远有这列；但**档案库是当年的快照**，v5 的包里根本没有 `entry_photos.slot`。查看器复用主库那套读记录的代码，直接 `SELECT slot`，于是 `SQLITE_ERROR`。

同类问题在别处已经处理过（`archive.ts` 用 `tableExists()` / `pragma table_info` 探表探列），只有这条记录读路径漏了。

## 影响范围

- v5 及更早的档案包：查看器不可用（合并、校验、清库不受影响）
- v6 及以后的档案包（有 `slot`）：正常
- YG 现有档案是 2026-11-11 打的（v7），**当前不受影响**；影响的是更早的历史包或别的机器上的旧包

## 修复建议

在照片读取路径上加一次**列存在性探测**（`pragma table_info(entry_photos)`）：
- 有 `slot`：照现在读
- 无 `slot`：退成 `NULL AS slot`（与 `archive.ts` 里「老包 v5 用 `NULL AS slot`」的既有做法一致，**不猜位置**）

注意：**不要在读取时按顺序兜底成 IN/OUT**——那是 `IS-014` / `D-025` 已经明确取消的行为（「不猜位置，不画假角标」）。老包的照片就该没有角标。

## 复现路径

1. 造一个 v5 档案包（跑到 `006` 之前的 schema，或直接用 `archive.test.ts` 里现成的 v5 夹具思路）
2. 档案柜 → 选该档案 → 「打开」
3. 观察：报 `SQLITE_ERROR: no such column: slot`，页面空白

## 复现率

v5 包 1/1；v6/v7 包 0/1（不受影响）

- [x] 校验 22 项与合并/清库不受影响
- [x] 需要补测试用例？是（已补 2 条：老库 5 张全 `slot: null` 且无 `'IN'`/`'OUT'`；v9 主库 `IN`/`OUT`/未标 三张逐字不变）

## 修复记录（2026-11-11）

**改法**（`src/main/repo/entries.ts`）：新增 `entryPhotosHaveSlot(db)`（`db.pragma('table_info(entry_photos)')`，与 `services/archive.ts#archiveEntryPhotoHasSlot` 同款）+ `entryPhotoSlotSelect(db)`（有列 → `slot`；无列 → `NULL AS slot`）；两处照片读取 SQL 都改用该片段：`photoRowsOf`（`photosOf` / `photosForEntry` / `getEntry`）与 `photosOfMany`（`listEntries` / `entriesAtKey`）。

**明确没有做的事**：**不**按顺序兜底成 IN/OUT。`IS-014` / `D-025` 已取消「NULL 猜位置」——老包的照片就该没有角标。

**证据**：`npx tsc` 两个 0；`npm run test` **27 文件 / 663 passed | 4 skipped**；修前探针在 v5 形状表上复现 `SQLITE_ERROR | no such column: slot`，修后读回 `[{"entry_id":1,"photo_id":1,"slot":null},…]`。

**同类点（已核查，本次不改）**：
- `src/main/export/xlsx.ts:1059` 的 `ep.slot AS slot`：所有导出通道都传主库 `getDb()`，够不到老档案库 → 当前不是活 bug；**若将来给档案加导出，先在这里加探测**
- `services/archive.ts` 其余 `ep.slot`：`collectRangeData` 打在主库；`countSlotDrift` 已在 `archiveEntryPhotoHasSlot` 门后
- `repo/photos.ts` 的 `photosForEntry`（同名不同物，引用计数）与 `summary.ts` / `payroll.ts` 不选该列
- `linkPhotos` 的 `INSERT … slot` 对无列老库仍会崩，但**写只发生在主库**（档案库只读；合并 = 读档案写主库），主库必已迁移
