# IS-004 金额取整方向改为「只入不舍」（向上取整到分）

状态：**已完成（2026-11-06）** —— `calc.ts` 三条取整出口全部改向上，`roundDivHalfUp` 已删除，306 passed / 2 skipped
发现日期：2026-11-06
提出人：YG

## 现象与现状

现在金额的取整规则是**四舍五入**（`round half up`，0.5 分往上）。用户要的是**只入不舍**：不管余数多少，一律进位到分。

| 精确值 | 现在（四舍五入） | 期望（只入不舍） |
|---|---|---|
| 100.663 元 = 10066.3 分 | 100.66 元 | **100.67 元** |
| 16666.6667 分 | 166.67 元 | 166.67 元（同） |
| 5555.5555 分 | 55.56 元 | 55.56 元（同） |
| 恰好 675000 分 | 6750.00 元 | 6750.00 元（同） |

**动机很明确**：宁可公司多给几分，也不能少给工人一分。

## 为什么现在不是「两位小数」那么简单

库里存的是**整数分**（一分 = 0.01 元），不存在「保留两位」这种格式问题。真正的差别只在**取整方向**：

- 四舍五入：余数 < 0.5 分时舍掉
- 只入不舍：只要有余额数就进位（`ceil`）

## 影响面

| 位置 | 影响 |
|---|---|
| `calc.sumAmounts`（行金额与合计） | 三处取整点改为 `ceil` |
| `calc.entryAmounts`（逐条，现仅明细展示用） | 同步改 `ceil`，避免两套方向并存 |
| `calc.exactCentsText`（明细 3 位） | 同步改 `ceil`，保证「明细不小于精确值」 |
| 工资表 / 结算单 / 导出 xlsx | 跟随上游，无需单独改 |
| **附录三人的验收数字** | **一个都不变**（全部整除，ceil 与 round 同值） |
| 真实数据 | 每项每人每区间最多多给 **0.99 分**，方向恒为「公司多付」 |

## 验收标准调整

E-3 原来写「明细 3 位相加与合计之差 ≤0.01 元」。改成 `ceil` 之后，每条明细向上最多进 0.001 元、合计向上最多进 0.01 元，n 条累计差的上界随条数增长。改为写公式而不是写死数字：

> 明细 3 位相加与合计之差 **≤ 0.001 × 明细条数 + 0.01 元**，且**合计不得小于三项精确值之和**。界面注明「合计按精确值向上取整」。

（写死 0.05 是不对的：一人一天可录上午+下午两条，一个月最多约 62 条，上界会到 0.072 元。）

## 实现要求

1. `src/shared/calc.ts`：把金额取整从 `roundDivHalfUp` 换成一个明确的 `ceilDiv`（整数运算，`num > 0` 时 `(num + den - 1) / den`；`num === 0` 返回 0；**禁止浮点**）。
2. 保留「一次性取整」不变：仍然按区间精确累加后再 ceil，不要退化成逐条 ceil 再相加（那是 A 路径 + 向上，误差反而放大 n 倍）。
3. 测试：
   - 附录三人数字**不变**（防回归）
   - 3×100 分钟用例：C+ceil 仍为 **16667 分**（16666.6667 → 进位 16667）
   - 新增用例：`10066.3 分` 的输入 → 期望 **10067**
   - 新增用例：恰好整数（675000）→ 仍 675000，不多进一分
   - 新增用例：`0.0001 分` 级别的极小余数 → 进 1 分（证明「有零就进」）
   - 明细 3 位文本：`5555.5555 分` → `"55.556"`（向上）；`5555.5000` → `"55.555"`（恰好不多进）

## 代价与提醒

- 每个分项每人每区间**最多多付 0.99 分**；三个人一个月最多几分钱，一年几百条记录量级仍在几毛钱内。
- 好处是「永远不少给」，对账时人事的心理负担最小。
- 若将来要精确到「正好应付」，得改回 round 或分段，不建议。
