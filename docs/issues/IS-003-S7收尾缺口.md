## 1. 已发放区间的锁定，只拦住了预支侧，没拦住考勤侧

**现象**：结算单标记「已发放」后，再记预支会被拦下（`E_VALIDATION`，文案带结算单号与区间）。但同一天**改考勤记录**（新增、覆盖、并入、删除）仍然通过，而那会直接改变已结算区间的应发金额。

**为什么是问题**：锁定存在的意义就是「发完钱不许再动」，只锁一半等于没锁。人事年底发完钱后补录一条记录，下一次打开结算单，实发金额就变了，而钱已经发出去了。

**根因**：`entries.ts` 侧被冻结（S7 任务边界），只有 `settlements` 的 `isLocked(db, date)` 可用。

**建议落点**：在 `src/main/ipc.ts` 里给 `entries:create` / `entries:overwrite` / `entries:update` / `entries:merge` / `entries:batchCreate` / `entries:delete` 加一道前置校验：拿载荷里的 `work_date` 调 `isLocked`，命中就返回 `E_VALIDATION`，文案与预支侧保持一致（带结算单号与区间）。**不改 `entries.ts`**。

**验证**：结算单标已发放 → 同一区间内新增/修改/删除考勤各被拦一次 → 解锁后同一操作成功。

## 2. 预支没有凭证截图

**现象**：RQ-001「预支台账」第 1 条写「可挂凭证截图（复用照片池）」，但 `advances` 表没有照片列，界面也没有挂图入口。

**为什么是问题**：支钱是现金或微信转账，没有凭证就无法对账。这是 YG 提的需求原文，不是可选优化。

**建议落点**：`004_advance_photo.sql` 加法迁移给 `advances` 加 `photo_id INTEGER NULL REFERENCES photos(id)`；`Advances.tsx` 复用照片池的选择器与 `att-photo://` 预览；按年份归档时凭证随区间照片一起进包（S8 注意）。

**验证**：记一笔预支并挂一张图 → 列表可见缩略图、点开原图 → 删照片时按「被引用」规则处理 → 导出/归档带上引用关系。

## 结案说明（2026-11-13）

**第 1 条「考勤侧锁定」——作废，不修。** D-026（2026-11-11）取消了**全部**四个方向的「已发放锁定」（考勤侧 / 照片侧 / 改价侧 / 归档侧）。本工单要补的正是「考勤侧那一半」；锁本身没了，补它等于给一个已删除的机制补零件。**否决「照原方案补上」**：那会让「发过钱之后照样能补录、改、删考勤」这条 YG 明确要的行为重新被拦住。

**第 2 条「预支凭证截图」——已完成，且做成了多张。**

- `Advances.tsx`：撑满宽 × 高 96 的多张拖入区；点缩略图开 `PhotoLightbox`；右上角 × 只解引用不删文件
- 「被引用」口径已收口到 `repo/photos.ts#refExpr` 一处（考勤 + 预支凭证 ∪ 老单列 + 发放凭证），见 D-030 与 `map.md` 那条坑
