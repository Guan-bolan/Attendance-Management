## 1. 这是什么，装在哪

单机 Windows 桌面软件，一个人用（公司人事）。它承接的是「照片归档 + 汇总 + 算钱」这一段：每天在微信群收工人拍照打卡，把照片与工数、加班、工地归属、日薪餐补记进软件，按月出工资表，发了钱就在「工资发放」里记一笔、随时看每人还差多少，年底按年归档。打卡本身仍在微信群完成。

**发钱这件事怎么用**（不用再凑「一张单」）：打开左侧「工资发放」→「记一笔发放」→ 选人（可以一次选好几个，每人填自己的金额）、填实际给出去的钱和发放日期 → 保存。页面上的「结余」表按人列出累计应发、累计预支、累计已发和截至今天的总结余，谁还差多少一眼能看到；点人名能看这个人以前发过哪几笔。记错了：当天记错的直接点「改」，改金额和备注；隔了天才发现就点「冲销」，记一笔等额负数抵掉，原来那笔留着不删。日期和工人改不了（要改就冲销重记）。发过钱**不会锁住**考勤和价目，以后补录、改价都照常。

**想拿一张表对账、或者发给别人看**：在「工资发放」页点「导出」→ 选时间段（默认就是页面上正在看的那一段，可以改），再选导谁（全部人，或者某一个人单独一份）→ 得到一张 xlsx。上面是这段时期的每一笔发放明细，下面是「截至今天各人总结余」，每人一行。金额都是能直接求和的数字，没有合计行（要合计自己在 Excel 里拉），冲销的负数也照实列着。

**不需要装 Node、不需要装数据库、不需要联网。** 目标机器只要 Windows 10/11 64 位即可。

两种形态，装一个就行：

| 形态 | 文件 | 适合 |
|---|---|---|
| 安装版（NSIS） | `鑫淼考勤-安装版-0.1.0.exe` | 长期用这台机器，要桌面图标、开始菜单、能从「应用和功能」卸载 |
| 绿色版（免安装） | `鑫淼考勤-绿色版-0.1.0.exe` | 拷到 U 盘 / 另一台机器临时用，不写注册表、不建快捷方式 |

两个 exe 用的是同一份程序，数据目录也一样（第 3 节）。**不要同时开两个**——软件有单实例锁，第二个会自己退出并激活已开着的窗口。

## 2. 安装 / 首次启动

### 2.1 安装版

1. 双击 `鑫淼考勤-安装版-0.1.0.exe`。
2. **Windows 会拦一下**：蓝底提示「Windows 已保护你的电脑」。点 **更多信息 → 仍要运行**。原因见第 9 节（未做代码签名）。
3. 选择安装位置（默认在 `%LOCALAPPDATA%\Programs\鑫淼考勤`，装给当前用户，不需要管理员密码）。想装到 `D:\` 就点「浏览」改路径。
4. 装完自动启动一次，桌面与开始菜单会有「鑫淼考勤」。

### 2.2 绿色版

1. 把 `鑫淼考勤-绿色版-0.1.0.exe` 放到任意目录（例如 `D:\鑫淼考勤\`），双击即可。
2. 同样会遇到 SmartScreen，点 **更多信息 → 仍要运行**。
3. 绿色版每次启动会把自己解到临时目录再运行（首次启动比安装版慢 2–5 秒），**不要**把它放到只读介质（光盘、只读 U 盘）里跑。

### 2.3 首次启动会做什么

- 在 `文档` 下建数据目录 `%USERPROFILE%\Documents\Attendance\`；
- 建库 `app.db` 并跑完 9 个迁移（`schema_version = 9`）；
- 建空目录 `photos\`、`thumbs\`、`inbox\`、`snapshots\`；
- 打开主窗口（工人台账为首页）。

第一次启动如果弹「启动失败」框，按框里的恢复建议做（数据库被占用 / 文档目录不可写 / 迁移中断三种情况各有对应步骤）。

## 3. 数据在哪

**唯一位置**：`%USERPROFILE%\Documents\Attendance\`（即 `C:\Users\<你的用户名>\Documents\Attendance\`）。

| 路径 | 内容 | 能不能删 |
|---|---|---|
| `app.db` | 全部业务数据（工人、工地、考勤、照片索引、预支、发放记录、档案登记、设置） | **绝对不能** |
| `app.db-wal` / `app.db-shm` | SQLite 的日志与共享内存，正常运行时存在 | 只在软件关闭时、且 `app.db` 已备份的前提下可删 |
| `snapshots\` | 自动/手动数据库快照（`*.db`）：常规快照按「设置」里填的份数保留（默认 3 份）；另有迁移前快照最多 2 份，不占常规名额，所以最多 3 + 2 = 5 份 | 可删旧的，但至少留最近一份 |
| `photos\` | 打卡照片原图（按年月分目录） | 不能删，除非已归档 |
| `thumbs\` | 缩略图缓存，删了会自动重建 | 可删（只影响首屏加载速度） |
| `inbox\` | 收件箱：把照片扔进这里会被自动吸入照片池，处理完的移到 `inbox\processed\` | 可清空 `processed\` |
| `archives\` | 年度档案包（每个年份一个文件夹） | 不能删，那是归档后的唯一副本 |

设置页里的「三个目录」就是这三个路径的只读展示（数据根 / 照片 / 收件箱），照片目录可以单独指到别的盘。

## 4. 备份

四种，从省事到保险：

1. **退出即快照（自动）**：每次关窗口都会往 `snapshots\` 写一份 `*-auto.db`，常规快照按「设置」里填的份数保留（默认 3 份）。另有「迁移前快照」最多 2 份，不占常规名额——所以磁盘上最多 3 + 2 = 5 份。防手滑够用，防硬盘坏不够。
2. **手动快照（推荐每月做一次）**：维护 → 快照 → 「立即快照」，写一份 `*-manual.db`。
3. **整库压缩包（最保险，年底必做 / 换机器前必做）**：维护 → 快照 → 「立即备份（整库 zip）」。
4. **整目录冷备（最保险，年底必做）**：关掉软件，把整个 `Documents\Attendance\` 复制到移动硬盘或另一台机器。

   整个目录一起拷，别只拷 `app.db`——照片在 `photos\` 里，库只是索引。

### 4.1 整库压缩包（一键备份）

「立即备份」做的事：

- 弹保存框，**默认存到数据目录的上一级**（也就是 `C:\Users\<你>\Documents\`，不在数据目录里面），文件名形如 `鑫淼考勤-整库备份-20261112-1130.zip`。想放移动硬盘就自己改路径。
- 包里是**一份完整的整库**：数据库（自动先做一致性整理）、全部照片、全部年度档案、**快照史**、一份清单 `manifest.json`（里面有记录数、照片数、档案数，恢复时拿它核对）。
- 体积 ≈ 照片总大小（jpg 已经是压缩过的，zip 压不动多少）。一年照片几个 G，属正常。
- 备份可以取消；取消或失败不会留下半截文件。

三点要知道：

① 备份期间软件会**暂停收照片**（收件箱暂停吸入），备份完自动恢复。别在备份进行中往收件箱扔图。
② 照片目录里**多出来的、没登记的文件**不会进包（回执会告诉你几个）；**缺的**（库里有记录但文件没了）会直接**拒绝备份**并报缺几张——包必须「账图一致」，否则就是给未来埋雷。
③ **整库包不是给 OneDrive / 坚果云同步的**：同步工具抢文件锁会让备份或启动失败。放移动硬盘或另一台机器。

> 这套备份（第 3 条）和整目录冷备（第 4 条）二选一即可，冷备唯一多给的是「收件箱里还没吸进来的照片」——整库包**不含** `inbox\` 里未吸入的图与缩略图缓存（缩略图可自动重建）。平时用整库包就够，年底归档后再整目录冷备一份是双保险。

> 备份放哪儿都行，**别放在同一个盘**。也别让 OneDrive / 坚果云之类同步 `Documents\Attendance\`：同步工具会在软件写库时抢文件锁，表现为「数据库被占用」启动失败。

## 5. 恢复

### 5.1 用快照恢复（数据被误删 / 迁移失败）

有两条路：**在软件里点按钮**（推荐，多数情况用这条），或者**手工换文件**（软件打不开时用）。

#### 在软件里恢复（推荐）

1. 打开软件，左侧进「维护 / 快照」。
2. 「数据库快照」那张表里挑一份时间对得上的，点它右边的「恢复」。
3. 弹出确认框，点「恢复」。软件会先把当前库自动留一份「恢复前」快照（退路），再换成你选的那份，然后自己把连接重开——**不用重启软件**，列表刷新一下就是那个时点的数据。

这条路**不需要**关软件，也**不需要**手动改名或删文件。

两条必须知道的事：

① **恢复会把库里的设置一起带回那个时点。** 快照是整个库的副本，设置也存在库里，所以那个时点的设置会一起回来。

② 其中**照片目录 / 数据根 / 收件箱这三个目录不会回退**——按你这台机器现在的设置保留（否则照片会全部打不开）。但**「自动快照保留份数」会跟着回退**：如果回退后比原来的小，下次关软件就按回退后的份数轮转、把多出来的旧快照删掉。所以恢复完最好去「设置」看一眼份数是不是你想要的。另外标准工日 / 加班折算 / 餐补这几个数也会跟着回到那个时点，恢复完顺手核一眼。

#### 手工换文件（软件打不开、进不去界面时）

1. 关掉软件（任务管理器里确认没有残留的 `鑫淼考勤.exe`）。
2. 打开 `Documents\Attendance\snapshots\`，挑一份时间对得上的 `*.db`。
3. 把当前 `app.db` 改名留底（例如 `app.db.bad`），把快照**复制**成 `app.db`。
4. 删掉同目录的 `app.db-wal` 和 `app.db-shm`（如果还在）。
5. 重新启动。

> **这一步（第 3 步）不能省**：手工换文件这条路**没有**自动退路。软件里点「恢复」会先自动留一份「恢复前」快照，手工换文件不会——所以「先把当前 `app.db` 改名留底」就是这条路上唯一的退路。改名前先看一眼 `snapshots\` 里有没有更近的一份，别把唯一能救的库覆盖掉。

> 手工换文件这条路同样会把库里的设置一起带回那个时点，三项目录也一样（会回退成快照里的旧路径，照片可能全部打不开）；份数也会跟着回退。换完进软件先去「设置」把目录和份数核一遍。要省这个麻烦，就用上面那条在软件里点的路。

### 5.2 用整库包恢复（换机器 / 硬盘坏）

这是**换电脑、硬盘坏了、系统重装**之后的正路：拿一个整库 zip（第 4 节第 3 条那个），一步把库、照片、档案、快照全恢复回来，**不用手工改任何设置**。

#### 怎么操作

1. 新机器上装好软件，**先启动一次再关掉**（让它把目录结构建出来），然后重新打开。
2. 左侧进「维护 / 快照」。
3. 点「恢复数据（整库 zip）」，在弹出的框里选你那个 `鑫淼考勤-整库备份-….zip`。
4. 软件先做**预检**（只读，一个字节都不动），然后弹一个确认框，上面列着：包里有多少条记录 / 多少张照片、当前库里有多少、包里带几份快照、退路包会写到哪个目录、有哪几份档案不在包里、以及一句「恢复期间请不要关窗口」。**逐条看完再点「恢复」。**
5. 点「恢复」之后等它跑完（几个 G 的包要几分钟）。进度条会走，中途可以取消——**取消只在校验/解压阶段有效，一旦开始换目录就只能等它跑完**。
6. 跑完会弹一条**关不掉的提示**（顶部还有一条红条）：数据已经换成包里的那一套，**必须重启**。点提示里的「立即重启」就行；不想点也可以手动关掉软件再打开。**重启前所有写操作都会被拒绝**（记考勤、改价、记发放、备份都点不动），这是故意的。

#### 退路包会自动生成（这是你的后悔药）

- 点「恢复」之后、动手之前，软件会**自动**把当前整库打成一个退路包，写到**数据目录的上一级**（`C:\Users\<你>\Documents\`），名字形如 `Attendance-恢复前-20261112-163000-123.zip`。
- **同一个前缀只留最近 1 份**：下次恢复时，新的写好之后才删旧的。如果旧的那份正被别的程序占着删不掉，会留下 2 份——**不影响恢复**，回执会把两条路径都写出来，你自己删掉旧的那份就行。
- 它**包含快照史**（和正式备份包一样），但**不含**收件箱里还没吸进来的照片、也不含缩略图缓存（缩略图会自动重建）。
- 恢复完之后，维护页底部有一行常驻的「**最近一次恢复的退路包**」，点旁边的「打开所在文件夹」就能找到它。同一份信息还写在数据目录上一级的 `Attendance-恢复退路-最近一次.txt` 里——**重启之后也还在**，忘了路径就去那个 txt 看。
- 想「退回去」怎么办：**再点一次「恢复数据」，选那个退路包**。它就是一个合法的整库包，走的是同一条路。

#### 恢复完必须核的四件事

① **快照历史跟着包回来了，不是清空**。维护页的快照列表里就是包里带的那几份，都能用。（早期说法「恢复后快照史清空」已作废。）

② **数值口径跟着包走**：标准工日、加班折算、餐补默认额、快照保留份数**都是包里那台机器当时的设置**，不是你新机器上的。**恢复完去「设置」页看一眼这几个数对不对**——换机器时这一步不能省，否则算出来的工资是按别人家的口径。

③ **档案柜可能提示「目录不存在」**。原因：原机器把某份档案放在了别的盘（比如 `D:\档案`），那份档案**没进包**（预检和回执会逐条列出是哪几份、原来在哪）。处理办法：把那份档案文件夹**手工拷到新机器的数据目录里**，再到档案柜用「重指路径」指过去。**在重指好之前，不要清库、不要合并档案**——程序自己会拦住（找不到目录就拒绝），但别去试。

④ **照片目录**：恢复后照片统一放到新机器的数据目录下（`…\Attendance\photos\`）。原机器如果把照片单独指到过 `D:\照片`，这个设置**不会跟过来**——这是换机的必然代价，照片本身都在包里，不会丢。

#### 恢复失败时怎么自救（极端情况才看）

如果恢复过程中出了极端情况（比如磁盘突然掉线、文件被占用），程序会弹出一段带**四个路径**的提示：数据目录、被改名让位的旧目录、刚落位的新目录、以及退路包。

> **别自己删任何文件夹。** 把那四个路径截图发给我们。你的数据一定在其中两处——**旧目录**和**退路包**——都能拿回来。

慌着乱删、乱改名才是真正会把数据弄丢的动作（这条是血的教训）。

#### 两条铁律

- **恢复期间不要关窗口**。窗口的关闭按钮和退出都会被拦下（会提示「正在恢复，请等它结束」），别去任务管理器强杀。
- **恢复前把重要东西另存一份**。恢复是整目录替换：包里没有的东西——旧快照史之外的杂项、收件箱里还没吸进来的照片、缩略图缓存——恢复完就没了。真要留，先自己拷出去。

### 5.3 用整目录备份恢复（手工冷备那条路）

1. 装好软件，**先启动一次再关掉**（让它把目录结构建出来）。
2. 关掉软件，把备份里的整个 `Attendance\` 覆盖回 `Documents\` 下（同名覆盖）。
3. 启动，检查工人数、最近一个月的记录数、照片能不能点开。

> 有整库 zip 就用上面 5.2 那条路，比这个省事也更保险（它自己会先造退路包、会做包校验、会改写档案路径）。这条路只在「手上只有一份整目录冷备」时用。

### 5.4 从档案包恢复（把归档数据并回主库）

档案 → 档案柜 → 选中档案 → 「合并恢复」。规则是**只增不覆盖**：同日同人同工地同时段的记录判重后跳过，冲突清单会列出来给你看。所以同一批数据恢复两次不会翻倍。

发放记录也一起并回来，判重按 **（工人 + 发放日期 + 记账时刻）**，**金额不进判重键**：同一笔发放金额对不上时**不会重复记账**，而是列进冲突清单让你确认；金额也一样的直接跳过。冲销的那笔会跟着找到它抵的原记录，找不到就不并、进冲突清单。

## 6. 年度归档

年底发完钱、对完账之后做：

1. 先做一次「立即快照」（第 4 节第 2 条）和一次「立即备份（整库 zip）」（第 4 节第 3 条），再整目录冷备一份。
2. 档案页 → 选区间（默认本年初至今）→ 「生成档案包」。程序会建 `archives\<区间>\`，里面是 `manifest.json`（区间、记录数、照片数、区间指纹）+ `data.db`（独立完整库）+ `photos\`（该区间引用到的照片），然后跑 22 项校验并逐项列结果。
3. 校验全绿之后，才允许「清库」——把该区间的数据从主库删掉（删前再拍一份快照）。程序还会先查三道闸门：档案里是不是真有这段的全部数据（**含发放记录**）、档案是不是比主库新（归档后改过考勤/发放/照片位置就拒）、这段的账结清了没。**跨区间的照片不会删**，被其它区间引用的记录也不会删。

   清库点下去会先弹一个确认框，列出**这段时间每人四个数**：应发 / 预支 / 已发 / 净额。净额不为 0 的人会默认拦住，要勾上「我确认这段时间已结清」才让继续。为什么要你勾：程序只知道「哪天给了谁多少钱」，**不知道每一笔钱补的是哪一段时期**——补发通常记成当天，落在要清的区间之外，所以「这段时间净额不为 0」不等于「这段没结清」；反过来净额为 0 也不等于结清了。结没结清只有你知道，勾选就是你的确认，这张每人四数的清单会存进档案包留作对账凭据。

4. 档案包整个文件夹拷到移动硬盘 / 归档盘。档案是目录形态，可以原地改一条记录再拷走，不需要解包。

**清库被拒了怎么办 ——「作废重建」**：档案柜每行有「作废重建」。它做的事是：把旧档案目录**改名**成 `<原目录名>.superseded-<时间戳>`（**原样保留、一个文件都不删**，只是不再算作一份档案），然后按同一区间重新生成一份新档案；弹框里可以勾「只删登记，不顺手重建」，那就只销登记、目录照样留着。什么时候用它：① 清库时程序说「这段数据在归档之后被改过」或者「主库里还有档案里没有的发放/考勤」——说明档案比主库旧，重做一份再清；② 档案包本身坏了、或者想换个口径重新生成。它**一行主库数据都不碰**，不删任何考勤、预支、发放。

> 校验只证明「包内自洽」，不证明「包 == 主库当时」。所以清库前程序会重算区间指纹与 manifest 比对，对不上就拒绝清库。改这块代码前先读 `docs/decisions.md` D-015。

## 7. 升级与卸载

- **升级**：直接装新版本的 `鑫淼考勤-安装版-x.y.z.exe` 覆盖安装即可，数据目录不动。升级前建议先「立即快照」。
- **卸载**（安装版）：设置 → 应用 → 鑫淼考勤 → 卸载。**卸载不会删 `Documents\Attendance\`**（那是几年的考勤与照片，故意保留）。确认不再需要时手动删目录。
- **绿色版**：删掉 exe 就完事，数据目录同样保留。

## 8. 从源码重新打包（维护者看）

```powershell
# 本机 GitHub 直连不通（docs/decisions.md D-010），两条镜像都要设
$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'
$env:ELECTRON_BUILDER_BINARIES_MIRROR='https://npmmirror.com/mirrors/electron-builder-binaries/'

npm install          # postinstall 会跑 install-electron 取 Electron 二进制
npm run dist           # 构建 + 出 NSIS 安装包 → dist\鑫淼考勤-安装版-<ver>.exe
npm run dist:portable  # 构建 + 只出绿色版  → dist\鑫淼考勤-绿色版-<ver>.exe
```

产物都在 `dist\`（已在 `.gitignore` 里）。`dist\win-unpacked\` 是未压缩的程序目录，可以直接跑，用来排查「装出来坏了但源码没问题」这类问题。

打包配置的几条硬性约定（改之前先读 `electron-builder.yml` 的注释）：

- `files` 只放 `out/**` + `package.json`；`docs/`、`src/`、`.tmp/` 不进包。
- `asarUnpack` 必须包含 `better-sqlite3` 的 `.node`（`node_modules/better-sqlite3/prebuilds/*.node`）。
- `npmRebuild: false`：better-sqlite3 13.x 是 Node-API 预编译，本机没有 MSVC，rebuild 只会失败（D-010）。
- 不签名（D-007）。没有图标，用的是 Electron 默认图标。

## 9. 已知限制

1. **未做代码签名，首次运行会被 SmartScreen 拦。** 双击后是蓝底「Windows 已保护你的电脑」，点 **更多信息 → 仍要运行** 即可。之后同一台机器不再拦。杀软偶尔会报「未知发布者」，那是签名的缺失，不是文件有问题。
2. **heic 照片只入池、不转码。** iPhone 直接拍出来的 `.heic` 能被拖进照片池、能被引用、能归档，但在没有 HEVC 解码器的 Win10 上缩略图是占位图，界面会提示「转成 jpg 再导入」。要正经用 iPhone 原图，先在手机端设成「兼容性最佳」或导出 jpg。
3. **没有自动更新。** 升级靠人工拷新安装包覆盖安装，程序不会联网检查版本。
4. **只出 x64。** 32 位 Windows 与 ARM 版 Windows 需要另打 target。
5. **单机单人。** 没有账号体系、没有云同步、没有多人协作。两台机器各自的数据不会自动合并，要合并只能走「档案包 → 合并恢复」。
6. **没有应用图标**，任务栏与桌面显示的是 Electron 默认图标。
7. **照片目录不要放进 OneDrive 同步范围**，同步工具会锁文件，导致入库或生成快照失败。
8. **绿色版每次启动会解压到临时目录**，企业管控软件（禁止运行临时目录 exe 的策略）可能拦住；这种情况用安装版。
