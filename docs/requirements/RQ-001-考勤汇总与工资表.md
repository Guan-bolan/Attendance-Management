## 背景

公司人事每天在微信群里收工人拍照打卡，再手动汇总。原来用 Excel 记：把一摞打卡照片插进表格，然后自己数一个人干了多少个工、加了多少小时班，还要数某个工地一共用了多少工、加了多少小时。工资按日薪算，另带餐补。工钱年底一次性发，年内工人没钱就来支钱（预支）。

现在的问题：照片一多 Excel 又慢又乱；一张合影上站着好几个人，照片在表里被反复插；汇总全靠手算，慢且容易错；算错一处就是钱的问题，事后无从核对；预支散落在微信记录里，年底对不上账；往年数据堆在几十个 Excel 文件里，找不到也删不掉。

要做的是一个 Windows 桌面软件，把「照片凭证 + 每日工数加班 + 工地归属 + 日薪与餐补 + 预支台账」一次记住，汇总和算钱自动出结果，每个数字都能点开看到它是怎么来的；并且能按年份归档，把某一年的数据打包收起来、需要时再拿回来。

## 做什么

1. **工人与工地台账**：工人姓名、日薪、餐补（每天）、在职状态；工地名称、状态。
2. **每日考勤录入**：日期、工人、工地、出勤（上午 / 下午 / 小时）、加班小时、备注，挂照片；同一人同一天可拆到多个工地；**可补录过去任意日期**。
3. **照片池与引用**：拖入或从「收件箱」自动吸入，考勤记录**引用**照片而不复制；一张合影可被多人引用。
4. **按人汇总**：任意区间内某人总工数、总加班小时，并按工地分解。
5. **按工地汇总**：任意区间内每个工地总工数、总加班小时、参与人数。
6. **月度工资表**：按自然月算每人应发（工数 × 日薪 + 加班费 + 餐补），**不含预支扣减**。
7. **预支台账（支钱）+ 结算单**：按人记录每次预支；需要发钱时用户自选起止日期生成结算单，扣掉该区间内的预支，算出实发。
8. **导出 Excel**：汇总表、工资表、结算单、预支明细导出为 xlsx，数字为数值型可直接求和。
9. **按时间段归档与恢复**：把一段日期（通常一整年）的数据连同其照片打成一个档案包，可从主库清出去；需要时按时间段拿回来查看、编辑，或合并回主库。
10. **口径设置与覆盖**：标准工日时长、加班折算、餐补可全局设，也可针对某工地、某工人单独设。

## 不做什么

以下为 v1 明确排除项。**逐条确认，要保留哪条就划掉哪条。**

1. **不做照片内容识别**：不做人脸识别、不做 OCR 提取水印时间、不做「一张合影自动拆给照片上的每个人」。合影里有谁，由人事勾选。
2. **不做微信自动同步**：微信不开放群消息/图片导出接口，照片仍需人事从群聊另存到收件箱文件夹或直接拖入。
3. **不做工人自助端**：无小程序、无 App、无网页填报。
4. **不做考勤机 / 指纹 / 门禁硬件对接。**
5. **不做工资发放**：不算个税、不做银行代发、不做社保公积金；预支的钱怎么给出去也不管，软件只记账。
6. **不做月薪制**（YG 2026-11-05 定：只有日薪，用户只填日薪）。不做缺勤扣款、不做 30 天折算、不做月薪加班基数。
7. **不做多人在线协作**：v1 单机单人使用，不做账号体系与权限分级；不做云同步与远程访问。
8. **不导入历史 Excel，也不做期初结转**（YG 定：直接不算）。软件从启用那天开始记账，之前的历史留在 Excel 里。

| 18 | 判重键 | 考勤 = (工人, 日期, 工地, 时段)；时段 ∈ {上午, 下午, 整天, 按小时}。档案合并、重复提示、覆盖/并入都按此键 |
| 19 | 金额表示与取整 | 存储与内部计算一律整数分。**每条记录不预先取整**：保留精确值（整数分子/分母运算，禁止浮点）；**对任一查询区间，每人每个分项只取整一次**——该区间内全部记录精确值累加后**向上取整到分（只入不舍）**，保证永不少给工人；应发 = 三个已取整分项之和。明细展示到元后 3 位（同样向上）并注明「合计按精确值向上取整」（YG 2026-11-06 定）。**推论：区间不同结果会有分级别差异**（月度逐月相加 ≠ 全年一次取整），故发钱以「结算单所选区间」那一次取整为准 |

| 22 | 界面单位 | **界面上一律用「小时」**：折算过程、设置页、汇总、工资表、批量登记都不出现「分钟」字样。分钟只在数据库与 IPC 内部使用。例外：错误提示说明上限时可以说「超过 24 小时」（仍是小时） |

## 关键功能详述

### 3. 照片池、收件箱与补录

**照片池**：照片只存一份，考勤记录存引用。一张合影对应 5 个工人，若按记录复制，一个月 1000 张会变成 5000 份，备份与磁盘都会失控。

1. **两个入口**：① 直接拖进窗口；② 把微信群里的图批量另存到一个固定「收件箱」文件夹，软件自动吸入（收件箱路径可设）。
2. **按日期分组**：优先取拍摄时间（EXIF），没有则取文件日期；均可手动改。
3. **引用**：录入时左侧常驻「当天照片墙」，点缩略图打勾即绑定，可多选；照片本体不复制。
4. **批量登记**：选中一张合影 → 勾照片上的若干工人 → 一次生成多条记录（日期 / 工地 / 出勤默认值统一，逐行可改）。
5. **去重**：同一张照片拖两次只入池一次，第二次提示「已存在」并定位到它。
6. **引用保护**：删除被引用的照片时提示「被 N 条记录引用」，给「仅解除引用」「彻底删除」两个动作。
7. **补录**：录入日期可回填到过去任意一天；照片墙默认显示**所选日期**的照片，不是今天的。批量登记同样以所选日期为准。
8. **缺记录提醒**：启动时检查最近 30 天，若有整天没有任何考勤记录，提示「2026-11-03 至 11-05 共 3 天无记录，是否现在补录」，点进去直接定位到那天。

### 7. 预支与结算单

1. 每次支钱记一笔：工人、日期、金额、备注（用途），可挂凭证截图（复用照片池）。
2. 每人显示：累计预支、可支额度（结余）（= 累计应发 − 累计预支 − 累计已发，可为负并提示「已超支」）。旧式「剩余可支额度 = 累计应发 − 累计预支」作废（RQ-005 C13，见口径 21；验收 F-3 同此）。
3. 记录只增不改；录错用「冲销」记一笔反向金额，原记录保留。
4. **结算单**：用户自选起止日期（默认本年初至今）→ 列出每人「区间应发合计 / 区间预支合计 / 实发」→ 可导出 xlsx。这就是年底发钱的依据。
5. 结算单可标记「已发放」（是否锁定见未决）。

> **v6.9 修订（2026-11-11）**：本节第 4、5 两条的「区间 + 标记已发放 + 锁定」形态已被 `docs/requirements/RQ-005-发放记账与结余.md` 取代——**发放只记（工人、金额、日期），不按区间、不锁考勤**，结余 = 累计应发 − 累计预支 − 累计已发。本节其余部分（预支只增不改、冲销、可支额度）继续有效。

### 9. 按时间段归档与恢复

1. **生成档案包**：选起止日期（或用「按年」快捷选）→ 打成一个档案包，内含该区间的考勤、预支、工人与工地信息快照、**被该区间记录引用到的照片**、该区间用到的口径设置。包上写明：版本号、生成时间、区间、记录条数、照片张数。
2. **未引用照片**：不进档案包；归档前提示「有 12 张未归档照片不会被包含」。
3. **清理主库**：档案包生成后做完整性校验（能打开、条数与照片数对得上），通过才允许把该区间从主库删除；删除前强制自动留一份全库快照。
4. **档案柜**：已生成档案列在软件内（区间、大小、时间），可点开查看、可**编辑档案内容**、可重新指定文件位置。
5. **恢复进主库**：选中档案 → 合并模式：按「同一天同一人同一工地同一时段」判重，**只增不覆盖**，冲突项跳过并报出数量与清单；恢复前自动快照。

## 验收标准

编号 `组-序号`。每条 = 可执行动作 + 可观测结果。

### A. 台账与设置

- **A-1** 新建工人：填姓名、日薪、餐补 → 保存后出现在列表，条目数 +1；重开仍在。
- **A-2** 新建同名工人被拦下，提示「已存在同名工人」并给「仍然添加 / 取消」。
- **A-3** 改日薪：张伟 300 → 350 并把生效日期设为 2026-12-01 → 11 月工资表仍按 300，12 月按 350。判定：两个月分别核对。
- **A-4** 两级覆盖：全局标准工日 9、某工人单独设 7.5 → 该工人的记录按 7.5 算，其他工人按 9 算。判定：两条记录的工数分别正确，且界面上能看到该工人「继承自全局 / 自定义」的来源标记。
- **A-5** 口径固化：某条记录保存后把全局加班折算从 8 改成 6 → 该记录工资不变；点「按当前设置重算该月」并二次确认后，该月金额按 6 重算，且重算前自动生成快照。「判定：改前改后两次金额都能说出算式。

### B. 录入与补录

- **B-1** 勾「上午 + 下午」→ 1 工；只勾「上午」→ 0.5 工。
- **B-2** 填 3 小时（标准工日 9）→ 工数显示 0.33，界面可见「3 小时 ÷ 9 小时」折算过程（口径 22：界面不出现分钟）。
- **B-3** 同一工人同一天先记 工地A 上午、再记 工地B 下午 → 两条并存、不弹重复；按人汇总当天合计 1 工。
- **B-4** 同一工人同一天、同一工地、同一时段再录一条 → 弹「该工人 2026-11-03 上午在工地A 已有记录」，给「覆盖 / 并入 / 取消」。
- **B-5** 加班填 2.5 小时 → 保存后显示 2.5，不被取整。
- **B-6** 补录：把日期改成 3 天前 → 保存成功，该记录落在 3 天前那天，照片墙显示的是那天的照片。判定：汇总里出现在正确日期。
- **B-7** 启动时若有整天无记录 → 提示「共 N 天无记录」，点进去定位到那天。

### C. 照片池与收件箱

- **C-1** 拖入 30 张 **jpg / png** → 30/30 进池，按 EXIF 拍摄日期分组正确；失败项列在「导入失败」并写明原因。heic 单独一组：入池成功、缩略图为占位并提示「需转 jpg」（heic 的成功率不计入 30 张这一档）。
- **C-2** 往收件箱文件夹里放 10 张图 → 软件自动吸入，重复的不重复入池。判定：池内新增数正确。
- **C-3** 同一张拖两次 → 池内仍 1 张，第二次提示「已存在」并定位。
- **C-4** 一张合影被 5 条记录引用 → 池内显示「被 5 条记录引用」；记录里可见缩略图，点开为原图。
- **C-5** 删除被 5 条引用的照片 → 提示「被 5 条记录引用」；「仅解除引用」后记录照片位变空、照片仍在池中；「彻底删除」后从池中消失。
- **C-6** 30 张照片被 5 条记录引用后，照片目录内文件数仍为 30。判定：数文件个数。
- **C-7** 批量登记：选中 1 张合影、勾 5 个工人 → 生成 5 条记录，日期 / 工地 / 出勤一致，可逐条单改。

### D. 汇总

- **D-1** 按人汇总 2026-11-01～2026-11-30：张伟 22.5 工 / 25.5 小时；李强 20 / 0；王芳 21 / 10。判定：与附录逐格一致。
- **D-2** 张伟的按工地分解：工地A 18.5 工 / 工地B 4 工，分解之和 = 合计。
- **D-3** 按工地汇总同期：工地A 59.5 工 / 32 小时 / 3 人；工地B 4 工 / 3.5 小时 / 1 人。
- **D-4** 区间内无记录 → 显示「该区间无记录」，不出空表格、不报错、不显示 NaN。
- **判定规则（所有合计）**：显示值相加与合计显示值允许 ±0.01 差，因合计按精确值累加、明细按 2 位显示；此差不算不通过，但界面须注明「合计按精确值计算」。

### E. 月度工资表

- **E-1** 设置：标准工日 9、加班折算 8、餐补 15 元/天 → 张伟 2026-11 行：工数 22.5、基本 6750.00、加班费 956.25、餐补 337.50、应发 8043.75。
- **E-2** 王芳行：5460.00 / 325.00 / 315.00 / 6100.00。李强行：7000.00 / 0 / 0 / 7000.00。
- **E-3** 三项之和 = 应发合计（每项由该分项精确累加后**向上取整**）；手算复核 3 行一致；点开可见**每条记录的精确值（3 位）**与算式；明细 3 位相加与合计之差 **≤ 0.001 × 明细条数 + 0.01 元**，且**合计不得小于三项精确值之和**；界面须注明「合计按精确值向上取整」。
- **E-4** 月度工资表**不出现**预支列，也不扣预支。判定：先记一笔预支，工资表应发金额不变。
- **E-5** 改某条记录的出勤或加班后重开工资表，各项与合计同步变化，差额等于按公式手算的差值。
- **E-6**（2026-11-13 追加）**多选工人筛选**：工具条可选 N 个工人（默认「全员」= 不选）。判定三条：① 表格只显示这 N 人，**底部合计只累加这 N 人**（筛选后无行时合计为 0）；② 点导出 → 保存框默认文件名是 `工资表_<姓名>_<from>_<to>.xlsx`（1 人）/ `工资表_<N>人_<from>_<to>.xlsx`（N 人）/ `工资表_<from>_<to>.xlsx`（全员），产物**只含这 N 人**；③ 选中的工人该区间**一条记录都没有**时，导出**报错并且不产生任何文件**（在弹保存框之前就拦下）。**金额不受筛选影响**：同一人筛与不筛逐分相同（每行金额仍是该工人自己全部记录精确累加后一次性取整）。

### F. 预支与结算单

- **F-1** 给张伟记预支 500（2026-11-10，备注「生活费」）→ 列表出现该笔，累计预支 0 → 500。
- **F-2** 再记 300 → 累计 800。用「冲销」记 −500 → 累计 300，三笔都在列表里（不真删）。
- **F-3** 可支额度（结余）= 累计应发 − 累计预支 − **累计已发**（三个累计都按「日期 ≤ 本地今天」算，发一笔后当场变小）；旧式「剩余可支额度 = 累计应发 − 累计预支」**作废**（RQ-005 v6 C13，同口径 21）。预支超过已挣工资时显示负数并标注「已超支」，不阻止记录——**「可负、已超支标红」的行为不变**。
- **F-4** 结算单（2026-11-01～11-30）：① 在**未冲销**时，张伟行显示 应发 8043.75 / 预支 800 / 实发 7243.75；② 执行 F-3 的冲销后再看，预支行变为 300、实发 7743.75，差额恰为 500。点开可见该区间的每一笔（含冲销那一笔负数）。顶部须注明「本区间按一次性取整；与逐月相加可能差几分」。
- **F-5** 结算单导出 xlsx，打开无错，金额列可求和。

### G. 导出、快照与归档

- **G-1** 导出 xlsx 用 Excel 打开不报错、不提示修复；工数与金额为数值型，框选后状态栏能求和。
- **G-2** 数据库快照：点「立即快照」生成一份；关掉软件重开可选最近 7 份；用快照恢复后数据回到快照时点。判定：造一条记录→快照→再删该记录→恢复→记录回来。
- **G-3** 归档 2026：生成档案包并显示区间、记录条数、照片张数、大小、以及「N 张未归档照片未包含」提示；从主库删除 2026 后，2026 记录与照片都不在，2027 数据不受影响。
- **G-4** 档案柜打开 2026 档案 → 能看到该年汇总与工资表，数字与归档前一致（抽 3 人核对）；能修改档案内一条记录的备注并保存。
- **G-5** 把档案文件夹整体挪到别的目录（如 U 盘）→ 档案柜提示「文件夹找不到」，重新指定路径后可正常打开；`manifest.json` 与 `data.db` 不配套时拒绝打开并说明原因。
- **G-6** 把 2026 档案恢复到已有 2026 数据的主库 → 按合并、只增不覆盖执行，冲突条数与被跳过清单可见，主库原有记录未被改写。判定：抽查 3 条主库原记录前后内容一致。
- **G-7** 主库照片目录被外部删除后启动 → 记录仍在、可继续录入，界面提示「缺少 N 张照片」并给定位入口，不崩、不静默清空记录。
- **G-8** 300 名工人 × 30 天（约 9000 条记录）下，点「按月汇总」到出结果 ≤ 3 秒。判定：秒表计 3 次取平均。

## 约束

- **平台**：Windows 桌面端，Win10 / Win11 64 位；只做 Windows。
- **离线优先**：断网可用，数据只落本机，不外传。
- **照片存放**：主库照片在软件数据目录内（位置可改），记录存相对引用；档案包必须自包含（拷到任何机器都能还原）。
- **金额精度**：工数全程精确值参与计算；金额存储为整数分，**每条记录不预先取整**，每人每月的分项按精确值累加后一次性取整到分（口径 19）。
- **口径唯一**：标准工日、加班折算、餐补只在设置里定义（含工地/工人覆盖），所有页面引用同一处。
- **可核对**：每个金额都能点开看计算式与数据来源，不能只给结果。

## 已知风险

1. **照片引用模型必须一开始做对。** 若写成「复制照片进记录」，改引用要迁移全部历史数据。
2. **归档是唯一的数据出口，做错就是数据丢失。** 必须：生成后校验、删除前快照、恢复走合并不覆盖、档案自包含。
3. **口径固化 + 两级覆盖会让「为什么这个人是这个数」变复杂。** 界面必须能展示「本条记录用的是哪个工日 / 哪个加班折算 / 该值是全局默认还是该工人自定义」。
4. **显示 2 位、计算不取整** 会有 0.01 差，判定规则已写进 D 组，界面须注明。
5. **预支是真钱。** 只增不改、冲销留痕、不许静默删除。
6. **照片体积。** 一年几个 G，档案包也是。归档粒度与压缩策略进 SDS 前要定。
7. **收件箱自动吸入** 若路径指向一个混乱的大文件夹，会把无关图片吸进池子。需要白名单扩展名 + 吸入后在池里易删。
