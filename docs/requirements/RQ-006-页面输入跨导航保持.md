# RQ-006 页面输入跨导航保持

状态：**已定稿 v1**（2026-11-11，YG 逐条确认；改动走变更记录）
日期：2026-11-11
提出人：YG

---

## 背景

`IS-006` 已经让「每日录入 / 批量登记」做到：填了没提交的内容，切到别的导航再切回来还在（只在内存里，退出软件就没了）。这个体验现在只有那两页有，其它页一切走就重置。

YG 要求把这个行为扩到另外四页。

## 做什么

**范围**：汇总 / 工资表 / 预支 / 工资发放（四页）。

| 页面 | 要保住的内容 |
|---|---|
| 汇总 | 时间范围（起止日期）、当前视图（按人/按工地/全员）、选中的工人或工地 |
| 工资表 | 起止日期 |
| 预支 | 页面上那块「记一笔预支」表单：金额、备注、已选凭证照片 |
| 工资发放 | ① 时间范围筛选；② **「记发放」弹窗里还没保存的内容**（发放日期、选中的工人、金额、备注、凭证照片） |

**保持的语义**：
1. 切导航（页面卸载）不丢，**只在内存里**，不写磁盘、不写数据库、不进 `ui-prefs.json`
2. **退出软件就清空** —— 重开是默认状态
3. **没动过的控件仍显示默认值**：不能因为"上次留过"就把上次的值当默认值显示出来。默认值永远是默认值（例如时间范围默认本月、金额框默认空）
4. 提交成功后按各页既有行为清空或保留（**不改变现有提交后的行为**）

## 不做什么

1. 不做「草稿持久化到磁盘」（退出后恢复是另一件事，本期不做）
2. 不做跨页面的「未保存内容提醒」（切换时不弹确认框）
3. 不改任何页面的提交行为、校验规则、默认值
4. 不改「每日录入 / 批量登记」现有的草稿机制（`IS-006` 的成果不动）
5. 不把筛选条件写进 URL / 路由（本应用不是 Web 应用）

## 验收标准

- [ ] **1** 汇总页：选 2026-10-01~10-31、切到「按工地」、选某个工地 → 切到工资表 → 切回汇总：三个选择**都还在**
- [ ] **2** 工资表：填 2026-09-01~09-30 → 切走再回来，日期还在
- [ ] **3** 预支页：填金额 300、备注「生活费」、选 1 张凭证照片（**不提交**）→ 切走再回来，三样都还在
- [ ] **4** 工资发放页：时间范围改成上月 → 切走再回来，范围还是上月
- [ ] **5** 工资发放页：打开「记发放」弹窗，选工人、填金额 500、备注、拖入 1 张凭证（**不保存**）→ 关掉弹窗 → 重新打开：内容**都还在**（发放日期、工人、金额、备注、凭证）
- [ ] **6** **默认值不被污染**：全新启动 → 汇总页时间范围是本月、工资表是本月初到月末、预支金额框为空、发放页时间范围是本月、记发放弹窗金额框为空
- [ ] **7** **退出即清空**：按第 1–5 条填好未提交的内容 → 关掉软件 → 重开：全部回到默认（第 6 条的状态）
- [ ] **8** 提交成功后行为与现在一致（例如记发放保存成功后弹窗关闭、列表刷新、金额框清空）
- [ ] **9** 「每日录入 / 批量登记」的行为**没有任何变化**（抽查：文本 + 数字 + 照片三样都还能保住）

## 约束

- 只在渲染层实现（状态提升 / 统一容器），**不新增 IPC 通道、不改数据库**
- 不许把状态塞进 `localStorage` / `sessionStorage` / 磁盘文件（第 2、7 条要求退出即清空，落盘就违反）
- 页面里不许出现金额换算（沿用 `shared/calc.ts`）
- 保持现有的「整页只有一个滚动区」「列宽预算」等布局纪律（见 `docs/map.md` 已知的坑）

## 已知风险

1. **状态容器放在哪**：`IS-006` 的做法是把草稿提升到 `App.tsx`（页面切换时组件卸载、状态不丢）。四页都这么做会让 `App.tsx` 膨胀，**但这是既有模式**，一致性优先；如果实施时发现 `App.tsx` 已经太大，可以抽一个统一的 `drafts` 容器，但**不许两套机制并存**。
2. **弹窗草稿的坑**：`Payments.tsx` 的记发放弹窗现在每次打开都重置。改成"关了还在"之后，用户可能困惑「为什么打开就有一堆旧内容」。**处置**：弹窗里加一句小字「上次没保存的内容还在」+ 一个「清空」按钮；保存成功或用户点「清空」才归零。
3. **与凭证照片的交互**：如果发放弹窗的凭证是"导入到照片池"的，关掉弹窗后照片已经在池子里了（导入是即时动作）。所以「保持」的只是**选中的 photoIds**，不是"撤销导入"。这一点要在界面上不误导用户。
