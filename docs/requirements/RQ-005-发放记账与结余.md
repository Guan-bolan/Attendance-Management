## 背景

公司发工钱的实际形态：**干一年、年底结；甚至一次结不清，分几次给；每次只是「某天给了某人多少钱」。**

现有结算单是「选区间 → 全员一张单 → 标记已发放 → 整个区间锁死」，三件事都不对：区间是多余的（发放不对应时间段）、锁定是错的（发过钱照样要补录、改价、合并）、"结了多少"表达不了。

## 模型（YG 2026-11-11 确认）

**每个工人一本账**：

```
结余 = 累计应发 − 累计预支 − 累计已发        （三个累计都按「日期 ≤ 本地今天」）
```

- `累计应发`：该工人全部考勤算出来的钱（工数 × 日薪 + 加班费 + 餐补，走 `shared/calc.ts`，区间一次只入不舍）
- `累计预支`：该工人全部预支净额（含冲销的负数）
- `累计已发`：该工人全部发放记录的金额之和
- **想看"某段时间挣了多少、发了多少"用页面上的时间范围**（只是筛选窗口，不改变结余算法）；想要严格的区间报表用工资表

| C17 | 导出 | 按所选日期范围导出；含备注列；**默认含冲销行**；文件上印一行「截至今天各人总结余」；支持**按人单独导出**（一人一张） |
| C18 | 结余的统计范围 | **只统计主库里（即未归档）的数据**。归档清库后那段不再参与结余 |
| C19 | **发放凭证照片**（YG 2026-11-11 新增） | 一笔发放可挂**多张**凭证（与预支多凭证同一模式）。拖入或选本地文件 → 进照片池并把**拍摄日期设成该笔发放的发放日期** → 挂到这笔发放上。删照片只解除引用、不删原图；**冲销行不带凭证**（涨停的收据留在原记录上）；发放记录本身仍只增不改，凭证随记录保留 |

## 做什么

1. **记一笔发放**：选人（可多人）+ 金额 + 发放日期 + 备注；一次提交生成多行（每人一行），**整批一个事务**（失败全不落）。
2. **发放列表**：按日期倒序；显示 人 / 金额 / 日期 / 备注 / 是否冲销；可按人筛选、按日期范围筛选；可「显示/隐藏已冲销」。
3. **结余表**：每人一行 —— **主数字只留「还欠多少」**；「这段时间挣了」（`periodDueCents`）作核对参考；三个累计（应发 / 预支 / 已发）与算式**折进「看明细」展开区**，展开标题写明账期（`自 YYYY-MM-DD 起 · 上次清库之后`，取不到时写「自启用以来」）。结余为负标红；底部一行合计。

   > **v8（2026-11-12）改**：原设计六列同屏（`这段时间该发 / 这段时间已发 / 累计应发 / 累计预支 / 累计已发 / 截至今天总结余`）已退役。原因：YG 实际用起来发现「这段时间已发」这一列回答不了「9 月的账结清了没」——发放只记「钱哪天给的」（`paid_on`），11 月补发 9 月的钱时它落在 9 月区间外，于是那列显示 0，观感像"没记上"。改为「欠账语言为主、区间只作参考」。
   > 同时：**发放流水默认显示全部**（不按页面区间过滤，最近的在最上），页面区间只影响「这段时间挣了」这一列；记发放成功后的回执写明「已记：工人 · 日期 · 金额」+「他的欠款 X → Y」。
   > 代价（YG 已知并接受）：「9 月的工资发完了吗」这个问题页面**回答不了**——因为发放不归属月份。要回答得给每笔钱标"结的是哪段账"，那是另一套模型（见 RQ-007 的结转，只解决"未结清金额如何跨年保留"，不解决"逐月销账"）。
4. **时间范围**：默认本月，含「本月 / 上月 / 本年」快捷；切换时只影响"这段时间"两列与列表筛选，**总结余不变**。
5. **未结清小字**：筛选行右侧 12px 浅灰小字（口径见 C12）。
6. **超发**：金额 > 该人结余时弹提示写清超出多少，确认后可存。
7. **冲销**：跨天的错记记一笔反向金额；原记录保留；列表里两笔都在。
8. **按人导出**：一个人一份凭据（帮他签字用）；也可按范围导出全部。
9. **按人查历史**：点开某人看到他全部发放记录与当前结余。
10. **预支页可支额度改口径**（C13）。
11. **拆掉全部锁定**（推翻性改动，逐条列清）：
    - 考勤的新增 / 修改 / 删除 / 并入 / 批量登记 前面那道「已结算并锁定」拦截
    - 照片的挂上 / 摘掉 / 彻底删除 前面那道拦截（就是 IS-012 刚加的那批）
    - 改日薪/餐补时「与已发放区间相交就拒绝」的检查（IS-008 末句）
    - 归档「区间内有已发放单就拒绝归档」、清库「有已发放单就拒绝」的规则
    - 结算单页的「标记已发放」「解锁」按钮与整个区间选择
    - 归档页/档案查看器里所有「结算单 / 锁定」相关的展示与提示
12. **清库前的两道保护**：① 该区间有人「期间净额」≠ 0 → **默认拦住**，弹窗显示每人净额清单 + 给「我确认这段时间已结清」勾选（勾了才能继续；清单无论勾否都写进 manifest 的 `clearance`；界面写明「程序不知道每笔钱补的是哪段时期，这里靠人确认」）；② 清库前的核对范围**加上发放记录**（现在只核对考勤和照片，会漏掉生成档案后补记的发放）。
13. **迁移**（C16）+ **自动备份**。
14. **文档同步**：`map.md` 的 P-11 / F-11、验收卡里结算单相关条目、导出文件名。

## 不做什么

1. 不做个税 / 社保 / 银行代发。
2. **不做任何形式的考勤锁定**（本轮明确推翻）。
3. 不做"这笔钱结的是哪几天"。
4. 不做打印（只做导出，打印在 Excel 里做）。
5. **发放凭证照片**（v7 新增）：记发放的弹窗里有一个拖入区，可拖入或点选多张本地图片；导入后进照片池、拍摄日期自动设为**该笔发放的发放日期**，并挂到这笔发放上；列表里显示凭证数量，点开可看；删除照片只解除引用。
6. 不做审批流、多人协作、云同步。
7. 不改工资表与汇总页的算法（只改预支页的可支额度口径）。

## 约束

- 金额一律整数分；取整走 `calc`（D-013 / D-014 只入不舍，区间一次取整）。
- **发放记录只增不改**（跨天纠错走冲销）；录入当天允许原地改正。
- 结余**只有一处实现**，页面不许各算一套。
- 新增迁移只许加法；`settlements` 的 `period_from / period_to / status / paid_at / unlocked_at` 废弃但**不删列**，界面不再读。
- 拆锁是**删除行为**：被删的拦截点必须逐条列在 SDS 里，验收第 9、10 条逐条确认。
- 一次提交多人多笔必须单事务；提交按钮要防双击。
- **发放金额上限 100 万元（`10^8` 分）**，超过则拒绝（不复用日薪/餐补那个 1 万元上限）；**负数只由冲销产生**（录入框不许填负）；**0 元不许存**。

## 已知风险

1. **历史账目变成可变的**：取消锁定后，改一条旧考勤会改变"当年发的够不够"。这是 YG 要的取舍，对账以导出的「截至日结余」为准。
2. **追溯改价会让结余跳动**（IS-008 已实现）：界面要让"应发是按当前价算的"可见（工资表已如此）。
3. **清库是不可逆的**：靠 C15 的两道保护 + 清库前快照。
4. **结余只统计主库**（C18）：归档清库后那段不再参与；用户查历史要去档案里看。
5. **`settlements` 的死列**：本期不删，SDS 要写明不再读、不再写。

## 未决问题

无（C1–C18 已全部定案；两颗质询的 ★8 条已定，A9–A16 已并入 C11–C17）。
