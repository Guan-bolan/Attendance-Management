# RQ-002 汇总页的日历视图

状态：**已定稿 v2**（2026-11-06，四个口径已由 YG 确认）
日期：2026-11-06
提出人：YG

---

## 背景

现在汇总页只有两张明细表：按人一行、按工地一行，都是「区间合计」。要回答「张伟这个月哪几天来了、哪天加了班」得自己翻每日录入，或者靠眼睛在长表里找。

需要的是**一眼看出一整个月**的形态：横轴是日期，纵轴是人或工地，格子里是当天的量。

## 做什么

在「汇总」页增加两个**日历视图**（与现有明细表并列，用页签或分段控件切换）：

### 1. 按人 · 日历

- 行 = 工人（按姓名 → 同名序号排序），列 = 当月 1 号到月末
- 每个格子显示该工人当天的**工数**与**加班**（如 `1` + `2.5h`；半天 `0.5`；按小时 `0.33`）
- 空白天 = 当天无记录
- 行尾（或列尾）给该人本月合计：工数 / 加班小时
- 顶部给全月合计，与现有「按人」明细表口径一致

### 2. 按工地 · 日历

- 行 = 工地，列 = 当月日期
- 每个格子显示该工地当天的：**出勤人数** + **加班合计**（不拆上午/下午，一个数就是当天来了几个人）
- **悬停格子 → 弹出当天每人明细**：`张伟 9 小时`、`王芳 4.5 小时`、`李强 3 小时`（按人列出，时长用小时，口径 22）
- 行尾给该工地本月合计：工数 / 加班小时 / 参与人数

### 3. 两个视图共有的行为

- 月份切换（上一月 / 下一月 / 回到本月）
- 鼠标悬停格子 → 显示明细（谁、哪个时段、多少工、多少加班）
- 点格子 → 跳到「每日录入」并定位到那一天（便于当场改）
- 周末列、今天列做视觉区分
- 数据量：30 人 × 31 天 与 300 人 × 31 天都不许卡（300 人时允许虚拟滚动）

## 不做什么

1. 不做甘特图、不做工时热力图、不做导出图片
2. 不改数据库结构（现有 `entries` 已够用：`work_date` / `period` / `attend_minutes` / `units_micro` / `overtime_minutes`）
3. 不做跨月连续滚动（一次只看一个月）
4. 不在日历里直接编辑（编辑仍走「每日录入」）
5. 不改现有两张明细表的任何行为

## 验收标准

- [ ] 切到「按人 · 日历」，选 2026-11，张伟行显示 22.5 工（附录数据）；11-03 格子显示 `1` 且加班 `2h`（附录 fixture 是 1320 分均分到 11 条，每条 120 分 = 2 小时）
- [ ] 同月王芳行显示 21 工；李强行显示 20 工
- [ ] 切到「按工地 · 日历」，选 2026-11，工地A 行 11-03 格子显示**当天出勤人数**与**加班合计**（不拆上午/下午）
- [ ] 悬停该格子 → 弹出当天每人明细，逐人与「每日录入」里当天该工地的记录对得上（谁、多少小时、多少加班）
- [ ] 行尾合计与现有明细表的同人/同工地合计**逐格一致**
- [ ] 点任意格子 → 跳到「每日录入」并定位到那天
- [ ] 空月份（无任何记录）→ 显示空日历 + 「该月无记录」，不报错、不 NaN
- [ ] 300 人 × 31 天数据下，切换月份到出结果 ≤ 2 秒
- [ ] 界面不出现「分钟」字样（口径 22）

## 约束

- 只读：不新增任何写操作、不改 `entries`
- 聚合必须复用现有口径（工数走 `units_micro`、加班走 `overtime_minutes`、金额不参与）
- 渲染层不做计算，聚合在主进程（`repo/summary.ts` 新增查询）

## 已定口径（YG 2026-11-06 确认）

| # | 问题 | 结论 |
|---|---|---|
| C1 | 按人日历格子显示什么 | **同时显示**工数与加班（上行工数、下行加班小字），另给「只看工数 / 只看加班」开关 |
| C2 | 按工地日历怎么显示 | **不拆上午/下午**，格子只显示「当天出勤人数 + 加班合计」；**悬停弹出当天每人明细**（谁、干了多少小时、加班多少），让人一眼看清「当天几个人、每个人干了多久」 |
| C3 | 点格子跳哪 | 跳到「每日录入」的**那一天**，列表自动筛到该日 |
| C4 | 视图范围 | **只做自然月** |

## 流程判断

按 `WORKFLOW.md` §7「仪式阶梯」，判据是**错误代价 × 不确定度**：

- 错误代价：低（只读展示，不改数据、不碰金额口径）
- 不确定度：中（视图形态与人数口径需要你定）
- 跨模块：3 个（repo / IPC / 渲染层）

→ 走**主干简化版**：需求卡（本文）→ 简版计划（一页，不单独出 SDS）→ 实施 → 按上面 8 条验收。
**不需要**红队审（不改数据模型、不影响金额），但**必须**保留验收标准与收尾更新 `docs/map.md`。
