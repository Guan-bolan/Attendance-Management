# RQ-003 设置页可修改三个目录

状态：**已定稿 v2**（2026-11-06，D1/D2/D3 已由 YG 确认）；实施排在 RQ-002 之后
日期：2026-11-06
提出人：YG

---

## 背景

设置页现在把「数据目录 / 照片目录 / 收件箱目录」三个路径做成**只读展示**，并留了一行提示「目录暂不支持在界面改」。

现实需求：C 盘小、想把照片放大盘；或者换一台机器后数据目录想放别处；或者收件箱想指到某个固定的同步文件夹。

**三个目录的风险差别很大**，不能一视同仁：

| 目录 | 装什么 | 改错的后果 |
|---|---|---|
| 收件箱 `inbox_dir` | 只放待吸入的原始图片，吸入后进 `processed\` | **几乎无风险**，改错了只是吸不到新图 |
| 照片目录 `photo_root` | 所有考勤照片（`rel_path` 相对它） | 改了不搬文件 → **所有照片立刻变「缺失」**，考勤记录还在但看不到图 |
| 数据目录 `data_root` | `app.db` + `snapshots\` + `thumbs\` + `archives\`（+ 默认的 `photos\`、`inbox\`） | 改了不搬库 → **打开的是一个空库，看起来像「数据全丢了」** |

## 做什么

设置页三个目录从只读改成可改，但**按风险分三档**：

### 1. 收件箱目录（低风险，即时生效）

- 点「更改」→ 选目录 → 校验（存在 / 可写）→ 不存在则询问「自动创建？」
- 保存后**重启 watcher**，不需要重启软件
- 自动在新目录下建 `processed\`
- 界面显示当前监视状态（监视中 / 未监视）

### 2. 照片目录（中风险，走「迁移」）

- 点「迁移到…」→ 选新目录 → 弹出确认，写明：将复制 N 张照片（约 X MB）、校验后切换、**旧目录默认保留**（可勾「迁移成功后删除旧照片」）
- 流程：逐张复制（按 `content_hash` 校验）→ 全部成功才写设置 → 失败则中止并保留原设置，已复制的文件列出来让用户决定删不删
- **中断可续**：已存在且 hash 相同的文件跳过，不重复复制
- 迁移过程中界面显示进度（已复制 / 总数 / 当前文件），可取消（取消 = 中止但不改设置）
- 迁移前提示「建议先在维护页点一次快照」
- **禁止「只改路径不搬文件」**——那会让所有照片变缺失，界面不提供这个选项

### 3. 数据目录（高风险，走「迁移 + 重启」）

- 点「迁移到…」→ 选新目录 → 确认弹窗写明：
  - 将复制：库（`app.db`，用 `VACUUM INTO` 出一致副本）、`snapshots\`、`thumbs\`、`archives\`、`photos\`、`inbox\`
  - 复制后校验（库能打开且 `integrity_check = ok`、表数一致、照片张数一致）
  - **切换后必须重启软件**（当前进程还连着旧库）
  - 旧目录默认保留
- 流程：复制 → 校验 → 写设置 → 提示「已切换，请重启」→ 重启后从新位置打开
- **若 `ATT_DATA_ROOT` 环境变量存在**：设置里的 `data_root` 会被它覆盖，界面必须显式提示「当前由环境变量接管，改设置不生效」，并禁用「迁移」按钮
- **禁止「只改路径不搬文件」**

## 不做什么

1. 不做「只改路径不搬文件」的开关（三个目录都不给）
2. 不做自动清理旧目录（只提供勾选项，默认保留）
3. 不做网络盘 / 移动硬盘的可用性监测（用户自己负责，缺文件时靠现有的「缺少 N 张照片」提示兜底）
4. 不改 `rel_path` 的生成规则（始终相对 `photo_root`）
5. 不做多套目录配置 / 多用户

## 验收标准

**收件箱**
- [ ] 改到新目录（存在的）→ 保存 → 界面显示「监视中：<新路径>」；往新目录丢一张图 → 被吸入
- [ ] 改到不存在的目录 → 询问「自动创建？」→ 确认后创建并生效
- [ ] 改到不可写目录（如 `C:\Windows\System32`）→ 拒绝并说明原因，原设置不变

**照片目录**
- [ ] 池里有 30 张照片 → 迁移到新目录 → 进度走完 → 设置指向新目录 → 照片池全部能看、`countRefs` 不变、`photo_root` 下文件数 = 30
- [ ] 迁移中断（拔掉目标盘 / 手动取消）→ 设置仍是旧目录、旧照片仍在、能继续用
- [ ] 迁移到已有部分同名 hash 文件的目录 → 跳过已存在、只复制缺的，最终数量正确
- [ ] 迁移过程中界面禁用「迁移」按钮，防止并发

**数据目录**
- [ ] 迁移到新目录 → 校验通过 → 提示重启 → **重启后 `dataRoot` 指向新目录**、库能打开、快照列表与迁移前一致（原有那些 + 迁移时自动留的 `pre-migrate` 一份）、照片能看
- [ ] 迁移后把**旧目录改名/移走**再重启 → 仍能从新目录打开（证明启动读的是数据根指针，不是硬编码默认路径）
- [ ] 指针指向的目录不存在（盘没插）→ 启动即报错并退出，**不许**回退默认目录建空库
- [ ] 迁移中库不可写（另一个实例在跑）→ 拒绝并提示「请先关闭软件」
- [ ] `ATT_DATA_ROOT` 存在时 → 「迁移」按钮禁用 + 提示由环境变量接管
- [ ] 迁移后旧目录仍在（未勾删除时），且旧库文件未被改动

## 约束

- 迁移类操作**必须先备份/快照**，且失败不改设置
- 所有路径校验走同一个函数（存在性、可写性、是否在另一个目录之内——防止把数据目录指到它自己的子目录里）
- 界面文案不出现「分钟」（口径 22）
- 迁移期间主进程要挡住写操作（同 `purgeArchiveRange` 的做法），避免搬一半有人录考勤

## 已定口径（YG 2026-11-06 确认）

| # | 问题 | 结论 |
|---|---|---|
| D1 | 迁移成功后旧目录 | **默认保留**，提示「确认无误后可手动删除旧目录」；不提供「自动删除」作为默认 |
| D2 | 数据目录迁移时 `photos\` 与 `inbox\` | **一起搬**（它们是数据目录的子目录，不搬等于照片全丢） |
| D3 | 照片目录能否指到数据目录内部 | **允许，但界面要提示**：`thumbs` 不在 `photo_root` 内，C-6 的「数照片文件数」仍然成立；提醒「备份数据目录时会一起备到」 |
| D4 | 迁移数据目录后，重启怎么知道去哪找库 | **写一个数据根指针文件**（`userData\data-root.json`），启动优先级 `ATT_DATA_ROOT` > 指针 > 默认目录。指针指向的目录不存在时**报错退出**，绝不回退默认建空库——否则用户删掉旧目录后重启会得到一个空库，看起来像数据全丢 |
| D5 | 数据目录迁移时要不要额外留快照 | **要**，留一份 `pre-migrate`。所以迁移后快照数比迁移前多 1，验收里「与迁移前一致」按「原有那些 + 这一份」理解 |
| D6 | 照片迁移要不要也留快照 | **不要**。它不搬库，只搬文件；界面提示「建议先在维护页点一次快照」即可 |
| D7 | 迁移目标里已有同名但 hash 不同的文件 | **中止迁移**并列出冲突，**不许覆盖**——否则误指到另一套照片库会毁掉别人的文件 |
