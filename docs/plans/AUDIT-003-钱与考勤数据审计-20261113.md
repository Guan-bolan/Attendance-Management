## 2. 最有分量的正面证据（这轮的「钱没错」是怎么证明的）

1. **P1：独立 BigInt 有理数参考实现对拍** —— 工数折算**穷举 1,036,800 组**（std 2–1440 全偶数 × 出勤 1–1440）**0 差异**；结余从**四张原始表独立重算**，8 人场景 40 个字段 + 随机 60 人 300 个字段**全等**；「合计 ≥ 精确值之和且 < 精确值 + 1 分」360 个断言全过。
2. **P4：变异体反证** —— 把 `archive.ts` 复制出来**各改一行**：去掉区间闸豁免 → 复现 **+630.00 元**；去掉实时库查重 → 复现 **−630.00 元**。两条都与我台架断言正好相反，**证明那两道闸真的是 load-bearing**，不是摆设。
3. **P6：跨出口对账** —— 族(a) 五个出口 × 4 人 = **36 个金额格 + 12 个工数格 + 4 个加班分钟格，差异 0 处**；族(a)−族(b) 逐人**恰等于**「> 今天」那条的应发（张伟 39000 / 王芳 27500）；族(c)−族(a) 只在赵六差 **1 分**（C15b 明文允许）。
4. **P5：导出真写读回** —— 65 个金额格全是 `ExcelJS.ValueType.Number`、`yuanToCents` 读回**逐格 0 分差**；「筛与不筛逐分相同」+ 分域恒等式 `Σ(各人) = 全员` 四项各差 **0 分**。
5. **P7：数据搬家不动钱** —— v8→v12 迁移后三人结余逐分不变（59313 / 21875 / 38987）；快照恢复回到那一刻；整库恢复等于包内内容；`migrateDirs.test.ts` 36/36 绿。
6. **P2：编辑矩阵 16 格全对** —— 只改备注/照片/工地/加班/工时/时段 → 基线不变；改工人/改日期 → 重解。两个入口（`updateEntry` / `overwriteEntry`）**行为对称**。

## 3. 已修的四项

### 3.1 【真缺陷 · 会静默改字】备注截断把 emoji 切成半个 → U+FFFD

**P2 挖出，我独立复现**：

```
[emoji] 截断后长度=500 U+FFFD=1 末位码元=0xfffd truncated=true
```

kept 备注 `'a'` + incoming `'b'.repeat(497) + '😀' + 'c'`，拼成 500 码元后 `slice(0, 500)` 的切口正好落在 emoji 的两个代理之间 → 落库末位是 **U+FFFD（替换字符）**。**用户的备注被静默改字**，而且不报错。

**修法**：`repo/validate.ts` 新增 `truncateText(value, limit)` —— 按码元截断后检查末位是否为孤立高位代理（`0xD800–0xDBFF`），是就退一格。**5 处同型代码全部改走它**（`entries.ts#joinNotes`、`advances.ts`、`payments.ts`、`carryovers.ts`、`archive.ts` 的自动冲销备注），全仓 `slice(0, MAX_NOTE)` **0 残留**。

**反证**：修前 `U+FFFD=1`（红），修后 `U+FFFD=0`、长度 499（绿）。回归用例进仓库：`entries.test.ts` 的「并入备注截断不切坏代理对」。

**代价（写清）**：截断结果可能比上限少 1 个码元——这是丢掉半个字符的必然。比"多半个字"好。

### 3.2 【不一致】预支明细的「备注」列不截断

`export/xlsx.ts#writeAdvanceDetailSheet` 直接写 `note: row.note`，而**同族三处**（工资表明细 `:533`、日历明细 `:571`、发放明细 `:2171`）都走 `noteCellText`。后果：库里 250 字备注，发放导出读回 **201 字**（带 `…`），预支导出读回 **250 字**（原样）。

**修法**：改成 `note: noteCellText(row.note)`。**已验证** `xlsx.test.ts` + `payroll.test.ts` 共 130 条全过。

### 3.3 【不一致】`advances:export` 的 `scope`/`ids` 校验在保存框之后

`from/to` 已在框前校验，但「按人却没选人」要等到 `planAdvanceExportRows` 才抛——那时保存框**已经弹过 1 次**，用户白填一次路径（与 `payroll:export`、`payments:exportWorker` 的「先校验后 dialog」相反）。

**修法**：`ipc.ts` 在 `from/to` 校验之后、`showSaveDialog` 之前，按 `planAdvanceExportRows` **同一口径**补 `scope` / `ids` 校验（`scope` 只能 all / workers；按人时去重后的正整数 ids 不能为空）。

### 3.4 【测试强度】「遍历全部通道」对只读通道的断言太松

`migrateDirs.test.ts` 原来只断言 `not.toBe('E_DB_LOCKED')` —— **任何错误码都能过**，包括裸 `TypeError` 折成的 `E_UNKNOWN`。

**修法**：收紧成白名单 `[null, 'E_VALIDATION', 'E_NOT_FOUND', 'E_INVALID_PERIOD']`。收紧后 **36/36 仍绿**，说明现有 51 条只读通道在空载荷下确实只出这几类结果。
