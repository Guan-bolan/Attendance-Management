## 现状

仓库里只有文档，没有代码：

- `src/` 为空目录，无 `package.json`、无构建配置、无数据库文件
- **不是 git 仓库**（无 `.git`），所以「每步一个 commit」目前不成立
- `docs/map.md` 不存在（按阶段 0 规则，第一个垂直切片跑通后才建）
- 机器实测：Node v24.16.0 / npm 11.13.0 / Python 3.10.11 / Win10 22H2 64 位；**无 .NET SDK、无 Rust、无 MSVC/Windows SDK**——原生模块只能靠 prebuild，这是 S0 的首要验证项

所以本计划没有「既有模块」可引用。真正的风险不在改坏什么，而在**数据模型与打包链一次定错、后面全部返工**。

## 红队审结果与处理

红队交回 33 条（会挂 12 / 会返工 13 / 可接受 8）+ 11 个单向门 + 覆盖缺口 8 条。处理如下。

### 单向门：11 条全部当场定死

| # | 决定 | 结论 |
|---|---|---|
| 1 | entries 的时段与判重键 | 字段 `period` ∈ {AM, PM, FULL, HOURS}；判重键 = (工人, 日期, 工地, 时段)。不存时段则 B-4 无法触发、G-6 合并会误判并存记录 |
| 2 | 日薪/餐补历史价 | 新增表 `worker_rates(worker_id, daily_wage, meal_allowance, effective_from)`；工资按 `entry.date` 匹配「最近一条 ≤ 该日期」 |
| 3 | db 连接形态 | `openDb(path)` 工厂，可注入；主库与档案库各一实例（S8 要开第二个库） |
| 4 | 照片判重键 | `content_hash`（SHA-256）+ 唯一索引，先用 size 预筛 |
| 5 | 照片根目录语义 | 库存相对路径；改目录时提供「搬迁已入池照片」，按 hash 校验，中断可续 |
| 6 | 档案包形态 | **目录形态**：`manifest.json` + `data.db` + `photos/`（理由见 D-009） |
| 7 | 金额表示 | **整数分**存储与计算，显示时才转元 |
| 8 | calc 喝什么数据 | 只喝 entry 里**固化的**工日/K/日薪/餐补；覆盖值在**录入时**读取并固化，calc 不读当前设置 |
| 9 | 工人身份键 | `id` 主键，`name` 非唯一；界面用「姓名 + 序号」区分同名 |
| 10 | Electron / better-sqlite3 版本 | 钉死具体版本号；S0 必须验「打包后 asar 环境能否加载原生模块」；退路 `node:sqlite`（要求 Electron 内置 Node ≥ 22.5，故版本必须钉） |
| 11 | 迁移与快照 | 每个迁移在事务内；迁移前 `VACUUM INTO` 快照；迁移或快照失败即中止，不进入可用状态 |
| 12 | calc 的接口边界与聚合粒度 | 只暴露**逐条**函数 `computeEntry(entry + 该条固化的口径 + 该日生效价)`，区间汇总与工资表都由它累加；禁止「汇总走 SQL 聚合、工资表走另一套」两条路径。性能不够时优化索引与缓存，不许改数字来源 |
| 13 | 第一批工资表是不是发钱依据 | **不是**。第一批期间口径若有修正，历史金额要重算并逐人解释；正式发钱必须用第二批的结算单。S6 收尾须在界面与交付说明里写明这条 |

**里程碑 M1a（S4a 收尾）**：此时已能录一天真实考勤、能看工数与加班，**可开始真用**。这是第一批里唯一的中间交付点——S4a 完成就先给 YG 装一版，让他边录边提意见，不必等 S6。

**schema 冻结**：数据库结构在 **S3 收尾**冻结。因为 M1a 之后就会产生真实数据，晚于此时改表就要迁真实数据。

**第一批收尾判据**：能跑通一天真实录入，并看到三个人的钱；`calc.ts` 单测与 41 条中第一批的 32 条全过。

## 回滚方案

- **代码**：需要 git。由 YG 执行（我不代做提交）：`git init`、`git add -A`、`git commit -m "docs: RQ-001 + PL-001 定稿"`，之后每步一个 commit，做砸 `git reset --hard` 回上一步。
- **git 未就绪期间的替代**：每步收尾把 `src/`、`db/`、`package.json`、`docs/` 打成 `backup/step-<N>.zip`（排除 `node_modules`、`.probe/`、`dist/`）。
- **数据**：启动与退出各留一份 `VACUUM INTO` 快照，保留最近 7 份；迁移前额外留 `pre-migrate`。迁移失败自动中止并提示恢复。
- **schema 变更**：只做加法，不删列、不改语义；改语义走新增列 + 数据迁移，旧列保留一个版本周期。
- **整体方案失败**（Electron 在某台机器跑不起来）：S0 前失败零成本；S1～S4 期间无真实数据，可重来；**S5 之后已录真实数据，只允许加法迁移，不许弃库**。
