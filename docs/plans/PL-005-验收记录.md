**新发现（补证过程中挖出来的，不是本轮的改动）**：

1. **【中】退路包留在原位置时，用它再恢复会删掉源包并失败**（`migrateDirs.ts:2338-2359` 的轮转只豁免刚写出的 `finalPath`，不豁免 `input.packPath`）。修法：轮转循环里跳过 `resolve(full) === resolve(input.packPath)`。报错码也应从 `E_NOT_FOUND` 换成 `E_MIGRATE_FAILED` 一句人话。
2. **【低】「正在解压」阶段取消的回包形状与文档不一致**：`backupPack.ts:1377` 的 `canceledError()` 抛 `E_MIGRATE_FAILED`，而 `migrateDirs.ts:3119` 的取消分支只认 `err instanceof MigrateCanceled` → 走的是失败分支。界面（`MaintPanel.tsx:398`）只在 `result.canceled` 时显示「已取消：当前数据一个字节都没动」，否则显示「整库恢复失败 —— …已取消」。**数据安全，只是文案与回包不对。**
3. **【极低】`main/index.ts:325` 的 close 拦截文案写死「正在恢复整库」**，但判据 `isMigrating()` 对照片迁移 / 数据目录迁移同样为真 → 迁移时也会弹「正在恢复整库」。

**两条环境事实（给后续台架复用）**：本机**没有 pwsh 7**（只有 `C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe`）；`fs.openSync` 持有句柄**挡不住** `rmSync`（libuv 带 `FILE_SHARE_DELETE`），要挡删除必须用 `[System.IO.File]::Open(..., FileShare::Read)`。

### G-1 验收 8 的「删旧退路失败」——**没有自动化用例**

- **缺什么**：要在 Windows 上把旧的 `Attendance-恢复前-*.zip` 占住（持有文件句柄）才能让 `rmSync` 失败，vitest 里没有可靠、跨平台的构造手法；`rmSync(..., {force:true})` 在被占用时抛 `EPERM` 的行为依赖真实文件系统。
- **代码侧已就位**：`createRetreatBackup` 的轮转循环把删失败的路径收进 `kept`（`console.warn('[restore] 旧退路删不掉（只留 2 份，不影响恢复）…')`），回包 `keptBackups`，`MaintPanel.tsx` 回执显示「旧退路删不掉（磁盘上多留了 N 份，不影响恢复）：…」。**结论不会被改变**（删旧失败不中止恢复）。
- **怎么人工验**：① 先做一次恢复，得到一份 `Attendance-恢复前-*.zip`；② 用另一个程序打开它（7-Zip 里双击进入、或 `certutil -hashfile` 挂住，最简单是**在资源管理器里预览它**），保持不关；③ 再做一次恢复；④ 观察：恢复仍然成功、磁盘上有 **2 份**同前缀 zip、维护页回执里出现「旧退路删不掉…两份路径」那一行；⑤ 关掉占用它的程序，再做第三次恢复 → 应回到 **1 份**。

### G-2 验收 12 的「窗口 close 拦截」与「before-quit 拦截」——**没有单测，只有代码**

- **缺什么**：这两处是 `main/index.ts` 里的 Electron 生命周期钩子（`mainWindow.on('close', …)` 与 `app.on('before-quit', …)`），需要一个**真窗口 + 真退出流程**才能触发；现有测试是 node 环境，没有真窗口。给它们写单测要把 `BrowserWindow` / `app` 的整套事件模拟出来，测的会是 mock 而不是行为。
- **代码侧已就位**：`main/index.ts:318-332`（`close` → `isMigrating()` 为真则 `preventDefault()` + `dialog.showMessageBox`「正在恢复整库，请等它结束（完成会自动提示重启）」，只给「继续等待」一个按钮）；`main/index.ts:477-491`（`before-quit` → `isMigrating()` 为真则 `preventDefault()` 并**直接 return**，`snapshotOnQuit` / `shutdownDatabase` 都不调）。**`snapshotOnQuit` 的早退有单测**：`migrateDirs.test.ts` › `退出路径：恢复中 / 等重启(restore) 时 snapshotOnQuit 都不产生快照行与文件`（两个时点各断言 `snapshots` 行数与文件数前后不变）。
- **怎么人工验**：① 用一个**大包**（几个 G）起一次恢复，等进度条走到「正在解压」或「正在落位」；② 点窗口右上角 ×：应弹出「正在处理数据 / 正在恢复整库，请等它结束」，窗口**不关**；③ 再点一次 ×，仍然不关；④ 恢复跑完后点「立即重启」：软件应正常退出并自动重开，重开后**没有**重启提示、数据是包内内容；⑤ 补充验 `before-quit`：恢复进行中在任务栏右键 → 关闭窗口（走的是同一条 `close`），或恢复中按 Alt+F4 —— 都应被拦下。

### G-3 验收 2 的「对话框默认路径」——**没有被断言**
