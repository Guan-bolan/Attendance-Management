# 鑫淼考勤

Windows 单机桌面考勤与工资结算工具。给公司人事用：每天在微信群收工人拍照打卡，把照片和工数、加班、工地、日薪餐补记进软件，按月出工资表；发了钱记一笔，随时看每人还差多少；年底按年归档。

打卡本身仍在微信群完成 —— 这个软件只承接「照片归档 + 汇总 + 算钱 + 记发放」。

- 单机、离线，不装数据库、不装 Node、不联网
- 数据只在本机 `%USERPROFILE%\Documents\Attendance\`
- 安装版 / 免安装绿色版两种形态，同一个 exe 内核

## 它解决什么

工地的考勤是「照片 + 工数」两件事混在一起记的：群里一堆打卡照，人事要按人按天算工数、算加班折算、按工地归属分账、再叠上日薪和餐补出工资表。用 Excel 做这件事，照片和数字是分离的，改一次价要手工回溯所有历史，发过钱之后对不上账也说不清。

这个软件的取舍是：

| 场景 | 做法 |
|---|---|
| 收照片 | 照片池 + 收件箱监听目录，拖进去自动按内容哈希去重、按拍摄日期归位 |
| 记工数 | 每日录入一行六字段；两张合影 + 勾人 → 批量登记一次生成多条（单事务，整批回滚） |
| 算钱 | 改价即追溯重算；所有金额只从 `src/shared/calc.ts` 一个出口出，不允许页面各算一套 |
| 发钱 | 「工资发放」记一笔（谁、多少、哪天给的），结余 = 累计应发 − 累计预支 − 累计已发，随时看谁还差多少 |
| 记错了 | 只增不改：当天记错的原地改，隔天才发现就走「冲销」记一笔等额负数，原记录留着不删 |
| 归档 | 按年生成档案包（独立库 + 照片 + manifest），22 项校验；清库前过三道闸门 |

## 功能

| 页面 | 做什么 |
|---|---|
| 工人台账 | 姓名 + 日薪 + 餐补一次提交；多段价历史（改价追溯重算）、同名软拦、停用/删除（仅限无记录） |
| 工地 | 工地列表、同名软拦、停用启用、删除门 |
| 照片池 | 拖入即导入、按日期分组、缩略图与原图、引用计数、删除二选一、手动改拍摄日期 |
| 每日录入 | 一行六字段 + 照片槽位（上班/下班）、当天记录表可编辑、展开看折算过程 |
| 批量登记 | 两张合影 + 勾人（姓名/拼音首字母），一次生成多条，生成后高亮刚生成的行 |
| 汇总 | 按人/按工地/全员三视图，单对象大日历，点格子看当天明细，导出汇总或明细（可含照片） |
| 工资表 | 任意起止区间、多选工人筛选、三项明细与算式、导出 xlsx |
| 工资发放 | 结余表 + 发放流水 + 记一笔（凭证照片可多张）+ 当天改/冲销 + 导出对账单 |
| 预支 | 记预支、冲销、按人累计与可支额度（结余，可负）、多凭证、导出 |
| 归档 | 生成档案包、22 项校验、档案柜（打开/重指路径/校验/作废重建/清库） |
| 档案柜查看 | 只读四个页签（汇总/工资表/记录/发放）+ 编辑备注加班 + 合并回主库 + 体检 |
| 设置 · 维护 | 标准工日、加班折算、餐补默认、快照保留份数；三个目录可改；界面缩放；整库备份与恢复 |

## 数据在哪

**唯一位置**：`%USERPROFILE%\Documents\Attendance\`

| 路径 | 内容 |
|---|---|
| `app.db` | 全部业务数据（17 张表，schema v12） |
| `snapshots\` | 自动/手动数据库快照，常规快照按设置份数保留（默认 3）+ 迁移前快照最多 2 |
| `photos\` | 打卡照片原图（按年月分目录） |
| `thumbs\` | 缩略图缓存，删了自动重建 |
| `inbox\` | 收件箱，扔进去的照片会被自动吸入，处理完移到 `inbox\processed\` |
| `archives\` | 归档档案包（独立只读库 + 照片 + manifest） |

目录可以在「设置」里改，`ATT_DATA_ROOT` 环境变量可以整体接管（造数和自动化验收靠它，避免碰真实库）。

```bash

$env:ELECTRON_MIRROR='https://npmmirror.com/mirrors/electron/'; node node_modules/electron/install.js

npm run build      # 构建到 out/
npm run dist       # NSIS 安装包 → dist/

```

仓库根目录还有几个双击即用的 cmd（给非开发者）：`启动-开发版.cmd`、`启动-测试库.cmd`（用 `.tmp\测试库`，不碰真实数据）、`打包-最新版.cmd`、`打开-数据目录.cmd`。

造压测数据（只写 `.tmp/`，脚本硬拒主库）：

## 目录结构

```
src/main/          主进程：窗口、单实例锁、自定义协议、数据库、IPC 处理
  db/              openDb + PRAGMA、迁移（只加不删，当前 v12）
  repo/            按领域分文件的数据访问层，DB snake_case ↔ TS camelCase 只在这里转
  services/        照片、缩略图、快照、归档、目录迁移、整库备份恢复
  export/          xlsx 导出
src/preload/       contextBridge 白名单（由 CHANNELS 数组生成）
src/renderer/      React 页面与组件
src/shared/        纯函数、类型、常量（calc.ts 是所有金额的唯一出口）
scripts/           造数脚本
docs/              需求卡、计划、SDS、决策记录、工单、验收记录
```

## 三条硬约定

这几条是这个仓库里最容易被破坏、也最容易出钱算错的地方：

1. **三套单位不许混**：时间存分钟、金额存分、工数存 `units_micro`（×10⁶）。跨单位计算一律走 `src/shared/calc.ts`。
2. **金额只有一个出口**：`src/shared/calc.ts` 是纯函数，不碰 IO；`src/shared/**` 全部不读库不读文件。
3. **结余只有一个实现**：`src/main/repo/balance.ts`。预支页和发放页读同一处，页面不许各算一套。

另外：错误码统一 `E_xxx`；IPC 通道统一 `域:动作` 且只能加进 `CHANNELS`，处理器表漏一个通道 `tsc` 直接报错。

## 已知限制

- **只支持 Windows 10/11 64 位**。路径处理、单实例、打包配置都是按 Windows 写的。
- **没有代码签名**，首次运行会被 SmartScreen 拦一次（更多信息 → 仍要运行）。
- **单机单人**。没有多端同步、没有账号体系，数据在谁的机器上就是谁的。适合「一个人事管一个公司」的规模。
- **单实例锁**：同时开两个，第二个会退出并激活已开着的窗口。
- 绿色版每次启动会把自己解到临时目录，首次启动比安装版慢 2–5 秒，不能放只读介质跑。
